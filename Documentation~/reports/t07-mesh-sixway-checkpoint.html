具体拍了什么

正交和透视各拍 15 行：六个正反方向的光、基准、彩色环境球谐光、六向贴图 Alpha、颜色吸收、发光渐变、主贴图缩放偏移、Clamp、贴图强制 LOD0，以及镜像负缩放。A 为 G0 Frozen ShaderLab，B 为当前 ShaderLab，C 为实际生成的 Graph。96×96 linear RGBAHalf 的中心 44×44 区域逐像素比较原始 RGBA，无损 float32 原始帧全部保留。

  • 原实现保护：30 行 Frozen/当前 ShaderLab 全部 0 差；全部捕获的整帧数值有限，A/B/C 各行的重复帧均 0 差。
  • Graph 对照：27 行当前 ShaderLab/Graph 严格 0 差。正交的 MainTex-ST、正交的 Rig LOD0、透视的 Rig LOD0 各有 1 像素不等，最大单通道差 0.00048828125；原始失败照录。
  • 不是空图：14 个直接因果对照中，B 与 C 的画面都至少有 939 个内部像素变化；六个不同光方向也分别被拍摄。

为什么之前负缩放大面积不对

修复前的完整试验，镜像网格在正交有 1,780 个不同像素、透视有 1,340 个，最大差达 0.033203125；这不是用户要求略过的微弱差。Graph 顶点生成的副切线已带镜像缩放符号，而原 NBShader 的切线手性计算路径不同。此次只改 NB_FX 包内适配：恢复原切线符号与 half 精度，再按原算法计算六向环境光。最终两项负缩放都变为零差，没有去改官方 URP 或删功能。修前数值与历史。

更早的 v1 只收集 26 行就早停；v2 夹具误用了本项目 NUnit 没有的 Assert.Multiple，导入报 CS0117，因此没有有效渲染结果；v3 完整 30 行为 25 零差、5 失败，包含上述两项负缩放错误。旧 XML、raw、夹具源码、修前 HLSL 和四次导入日志都在档。这些测试夹具问题已处理，不是要求用户修改官方包的卡点。
