20 项测的是什么

这里的 A 是当前 NBShader 关掉程序噪波，B 是同一个当前 NBShader 打开它，C 是实际生成的 Graph 打开它。A 不是 G0 Frozen，所以本片不能被误读成 Frozen/当前的基线证明。2 项普通 Forward、9 项 NBCameraOpaqueDistortPass、9 项 NBDeferredDistortPass；128×128 linear RGBAHalf，中央 48×48 区域原始 RGBA 严格零差。

  • 画面一致：20 项的 B/C 主画面及“把 NoiseMask 改为白色”的控制画面都严格 0 差；A 与 Graph 关程序噪波也为 0。全部整帧数值有限，B/C 重复拍摄为 0 差，实际可见像素最少仍有 1,588 个，不是空图“通过”。
  • 功能会动，也会正确停止：改变噪波、遮罩时 B/C 都有明确响应；关闭纹理 Noise 后，程序噪波不能独自启动扭曲，这一点两边都保持。错误 Pass 模式、mode 0 和原设计的回退/无效模式不会误画。blend 值 4/5 是沿用原行为的回退，不能说新增了第 4/5 种噪波算法。
  • 避免遮罩乘两遍：Deferred Pass 把扭曲方向存在 RG、覆盖度存在 B，测试通过改遮罩后比较 RG/B 的派生比例来查是否重复乘遮罩。这里的 0.001 只是 RGBAHalf 数据做除法后的因果检测上界，不是截图零差规则的容差；实际派生差也测得 0。

最初 17/20 为什么失败

初版测试的两个 Forward 例子把物体放在 layer 3，但隔离 Renderer 的透明层遮罩值 55 没包含它，于是旧 Shader 和 Graph 都没画出来；最终夹具先读遮罩，再选允许的 layer 4，没有修改 Renderer 资产。另一个 Opaque 例子强度 0.5 只画出 61 像素，低于夹具“必须超过 100 像素”的防空图线；改为强度 2 后可见 1,588 像素，B/C 仍零差。初版指标文字还误把 A 称为 Frozen；实际它一直是当前 ShaderLab 关程序噪波。原始旧 XML、652 个 case 文件、夹具和两次导入/测试日志均保留，没有重写旧结果或把夹具错误当成用户卡点。

同一固定产品提交的完整回归为 1003 项：845 通过、158 严格失败、0 跳过。上次 SH 归档的 983 项里那 158 个失败身份全保留，没有新增/消失；PN2 新增 20 项全通过。46 项 GUI 存取测试没有截图，因此实际是 957 个画面对照目录，不是“1003 张图”。完整 XML · 失败身份核对。
