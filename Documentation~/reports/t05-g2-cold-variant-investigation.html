同源控制进一步区分了“生产/冻结 HLSL 不等价”与“同一 Shader 的首次/再次绘制不一致”：把 Dissolve 夹具两侧都临时改为同一生产材质和同一个生产 Shader 资产，在双重导入→正式 P4 后仍得到完全相同的首帧 1090 像素差，当前侧自身复画差 1090、复画两侧 0 差；原始失败与临时补丁。两侧都改为同一个 G0 Frozen Shader 资产时1/1。这证明 1090 首帧差不需要生产/冻结跨 Shader 比较就能出现，但不证明生产 Shader 代码或编译完全无责。

另一个仅用于诊断的夹具在正式模式循环前，先对双方显式启用 _DISSOLVE_MASK 的 mode0 并各画两次、保存四图；双导入→正式 P4 的 3 轮中，首次冷态 A/B 均 1090、当前首次→再次 1090、冻结自身 0、预热后 A/B 0，而随后正式模式循环1/1；第 2/3 轮数值相同。预热补丁已回退，正式测试保持冷态严格断言，不能把“预热后通过”代替首次失败。Editor 最终编译成功，所有临时诊断改动已恢复。

MatCap 是独立问题：连续四次双导入即使不先跑 P4 仍在正交/add/opacity1 的同一 (50,46) 像素得到当前红 140、冻结红 139，自身复画 0 差；先前Float RT 与常量/渐变纹理诊断见约 0.0002197623 浮点差并显示渐变采样相关，临时恢复原内联 MatCap 表达式仍失败。随后同源仅改 Shader 名称的独立资产对照也重现同一 1 像素差，因此不能将其直接归因于重构，更不能把它归为简单读回时序噪声或事后自行调整容差。正式夹具及两侧 HLSL hash留档。

后续进展：场景加载与首帧对照已证明空场景原 A/B 可因两边同错而假通过，正式测试新增两侧自重画检查；不同样例场景会交换首帧失败侧。逐侧 SetPass/可见 Player 补证进一步把 Editor 现象关联到各材质的首次准备状态；隔离最小 Player 的首个场景帧没有重现，但不能用 SetPass 预热或单一 Player 切片注销 Editor 失败。仍未定位具体变体/资源层，也未修复产品首帧。针对 MatCap 还需单独定位 UV/采样数值来源。G2–G7 不因 P4/P5 限定通过而放行；若需要修改 NBPostprocess、改变扭曲功能或调整 Gate 容差，将先提交用户决策，不自行变更。
