普通 Mesh 折射已接入 Graph；30 项中 25 项严格通过、5 项保留原样失败

人话结论：现在 Graph 的普通 Mesh 可以像原 NBShader 一样，用物体法线与折射率决定屏幕扭曲方向；扭曲方向继续进入已有的前向显示、相机不透明扭曲和延后扭曲路径。原 NBShader 的折射数学被抽成包内共享函数，旧入口仍调用它；Graph 不会把折射额外叠到纹理噪波上，也不会把遮罩乘两遍。当前只是这部分功能接入，不是全功能或 Gate 放行。

固定产品/测试提交 bf0942b979013ae5079029b5a5ab5027729368c4，6 条固定路径源码均从该提交无损保存；没有修改官方 URP、UniversalTarget、NBPostprocess、原 ShaderLab Pass 或 packed 协议。主 Agent 在独占隔离工程用 Unity CLI 验证；本证据归档者未启动 Unity、编辑产品/测试/中央索引/Git 或 push。

30 项怎样比

A 是不可变 G0 Frozen NBShader，B 是当前 NBShader，C 是实际生成的 Graph。普通 Forward、NBCameraOpaqueDistortPass、NBDeferredDistortPass 各 10 项，覆盖正交/透视、三个折射率，以及法线贴图、背面、程序噪波和全反射控制。每项保存 21 张 PNG、21 份可重算的 float32 RGBA 原始帧与指标：总共 630 PNG＋630 原始帧＋30 指标。测试检查主画面、关闭折射、遮罩改白、换折射率、换 NoiseMap、重复拍摄与有限数值，并用非零对照防止空图误过。

  • Frozen 未漂移：30 项 A/B 的主画面、关闭/遮罩控制均严格 0 差；B/C 的关闭控制也都是 0。B/C 重复拍摄全帧 0，全部捕获数值有限。改变折射开关或折射率在 B/C 两边都确实使画面变化，不是只接了属性而没有渲染。
  • 三项 Deferred 透视严格失败：B/C 主画面或折射率/遮罩控制出现非零差，最大 0.000030517578125。仍按严格 0 判失败；用户要求不追微弱颜色差，本轮保留原始像素和指标，不改容差，也不凭小幅值宣称“完全相同”。
  • 两项 Opaque 辅助断言失败：折射率 1 的正交平面和全反射理论上给零屏幕偏移。测试另加了“输出应与纯背景逐值相同”的严苛检查，B 与 C 各自都差 0.000244140625，但这两项的 B/C 本身严格为 0。因此它们是辅助零背景断言失败，不能写成 Graph 相对旧 Shader 不一致；目前也不把差异原因定论为某个采样边界问题。
