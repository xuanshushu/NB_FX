普通 Mesh 顶点位移与主颜色修正

人话结论：Graph 现在能像现有 NBShader 一样，按自定义方向、法线、顶点颜色或贴图颜色移动网格顶点。14 项普通 Mesh 对照全部通过，整张测试图的 RGBA 差为 0。初次失败不是细微色差，而是 Graph 的主颜色被错误地再转换了一次、明显变暗；改正主颜色的 HDR 属性后，用完全相同的测试通过。本片仅证明以下顶点位移场景，不表示所有 Mesh 功能已经完成。

2026-10-01；固定产品提交 64308ec，输入提交 58f2048。Unity 6000.3.18f1 / URP、SG、VFX 包 17.3 / Metal / RenderGraph。主 Agent 使用独占隔离 clone CLI，unityMCP 当时不可调用；主工程未打开。本轮没有真正 VFX 或 Player 测试，按 D24 先完成普通 Mesh 完整对照。

本片范围：让顶点移动，不是新增一套算法

  • Graph 只增加输入适配，调用原有 NBFX_ComputeVertexOffsetOSV1。支持本片的四种方向；RGB 方向需要按世界空间转换时，保留原算法不做额外归一化。
  • 位移贴图和遮罩各自取 UV，保留原 ST 缩放平移、动画顺序、通道、Wrap 和半精度赋值边界。顶点用 LOD0 采样；与表面共享已有采样器实现，不复制另一套。表面的 HDR 贴图解码继续保留。
  • 仅修改位置；法线和切线原样传递。旧 ShaderLab 的 GeometryV1、UVV1、Forward 和 Shader 源码与输入提交字节相同；本片不为 Frozen ShaderLab 加入新功能。

初次失败：主颜色被变暗，已修正产品，未放宽夹具

初次 649 项是 613 通过 / 36 失败，新增顶点 14 项全部失败，另有原来的 22 个 UV 失败。给两边设置同一个颜色 (0.9, 0.25, 0.13)，实际图中旧 Shader 约为 (0.900, 0.250, 0.130)，Graph 却约为 (0.787, 0.051, 0.015)。这不是 1/256 的微差，而是主颜色的类型设置错了，颜色又做了一次转换。

旧 Shader 的主颜色是 [HDR] _BaseColor，Graph 的 Color 属性当时仍为 LDR。产品仅将这个 Color 对象的 m_ColorMode 从 0 改为 1，匹配 HDR。对初次与最终 5 份源码的核对发现：Graph 对象语义只改了这一字段，顶点宿主、采样器、表面 CF 和测试源码字节完全相同；没有更换测试颜色、简化场景或调整阈值。
