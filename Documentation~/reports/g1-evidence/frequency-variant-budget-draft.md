The separate `multi_compile_fog` directive is shown separately; it is **not** interpreted into a numeric variant multiplier. A group count is **not** a variant count; Unity/URP platform preprocessing, mutually exclusive keywords, target stage, Graph-generated pragmas and build stripping are not evaluated.

Across passes, the existing `NBShaderFeatureCatalog.RawKeywords` has 65 names (`NBShaderFeatureCatalog.cs:23-93`). The eight pragma names outside that catalog are `EVALUATE_SH_MIXED`, `EVALUATE_SH_VERTEX`, `SOFT_UI_FRAME`, `UNITY_UI_CLIP_RECT`, `_ADDITIONAL_LIGHTS`, `_ADDITIONAL_LIGHTS_VERTEX`, `_CASTING_PUNCTUAL_LIGHT_SHADOW`, `_CUSTOM_LOCAL_TRANSFORM`. The first seven are associated with multi-compile groups in this shader; `_CUSTOM_LOCAL_TRANSFORM` is an explicitly separate runtime keyword used by `NBParticleLocalTransformHelper.cs:10-18,60-98` and declared in all seven passes (`NBShader.shader:654,787,896,954,1029,1154,1278`). Do not add it to the tier catalog merely because this inventory flags it external; this is a design boundary to evaluate.

**Critical scope boundary:** Existing `NBShaderVariantStripper.OnProcessShader` returns unless `shader.name == "Effects/NBShader"` (`NBShaderVariantStripper.cs:22-45`; `NBShaderFeatureCatalog.cs:14`). It can strip managed keywords and optional passes for current production NBShader (`NBShaderVariantStripper.cs:65-111`), but **does not automatically cover a differently named SG/VFX-generated shader**. The GF generated shader names differ in prior evidence; a product Graph needs its own explicit stripping/collection strategy or proof that existing build paths cover it. Existing SVC builder generates `ExactMaterialVariants` from NBShader materials (`NBShaderVariantCollectionBuilder.cs:151-185`) and cannot be claimed to cover product Graph/VFX without an implementation/test.

## Proposed incremental budget for G1 review, not approved

1. **No new `multi_compile` groups** in product Graph/NBShader unless a concrete platform requirement and build measurement justify one. Do not convert packed uniform selection or per-particle values into compile-time keywords merely for convenience.
2. **No unreviewed new named keyword groups**: track every Graph keyword (name, affected passes, who sets it, feature tier, stripping behavior, serialized default) and require an explicit delta from this snapshot. Existing NBShader remains untouched for URP Mesh.
3. **Pass budget:** preserve the two exact custom distortion LightModes shown by GF; compare generated product Graph/VFX pass lists to the 10/8 GF reference, and explain any additional or missing pass. Do not treat 10/8 as a permanent fixed count for all target configurations.
4. **Measurement budget still open:** before setting a numeric compiled-variant/import-time ceiling, capture current Unity 6000.3 import/compile time, shader variant count by generated Graph and VFX Output, Player retained variants/size, warm/cold import, and representative feature combinations. Lexical counts above cannot substitute for these. G1 may freeze a *measurement protocol* and zero-unreviewed-delta rule; numeric ceilings require Unity evidence and main-Agent approval.

## Current Unity GPU/Player items not run in this increment

- Full 32-bit packed flag round-trip in generated Graph and VFX shader, including bit31 / `_UVModeFlagType0` bit31 / CustomData high nibble. Existing GF Player covered controlled Pass output, not this bridge.
- Per-particle stream binding and interpolation for 8 CustomData channels, UV source selection, mask/dissolve/distortion and vertex displacement.
- Keyword state under Material, runtime helper, VFX Output, feature tiers and variant stripping after Player build. Previous GF Player result is not a product keyword matrix.
- Imported/generated Graph/VFX actual keyword groups and per-pass retained variants, shader compile duration, stripping reports, build size, GPU render outputs and performance. These require the current Unity 6000.3 serial validation lane; lower-version trials are deferred by D21.
