F0 ordinary-Mesh Flipbook — source-confirmed plan, 2026-10-01. Candidate only, not GPU proof.

A. Source contract
1. Old NBShader `NBShaderInput.hlsl:1200-1224` compiles `_FLIPBOOKBLENDING_ON` as `float4 texcoords:TEXCOORD0` (frame UV0.xy plus next-frame UV0.zw) and `float3 texcoordBlend:TEXCOORD3` (x is per-vertex blend weight; yz may carry particle special UV). TEXCOORD1/2 remain independent `Custom1/2`; `_FLIPBOOKBLENDING_ON` and `_VAT` are mutually exclusive only on four geometry passes. Unity Mesh uv4 is TEXCOORD3. Package SG UVNode `m_OutputChannel=3` gives UV3 float4; do not replace the legacy protocol with SG FlipbookNode's own frame math.
2. `NBShaderForwardPass.hlsl:159-223`: for `!isProcessUVInFrag()` it computes `ParticleProcessUV` at vertex, puts animBlendUV into varying and TEXCOORD3.x into half normalWSAndAnimBlend.w. For fragment-UV path (`:396-422`) it reruns ProcessBaseUVs/ParticleProcessUV and chooses `blendUv.xy`. `isProcessUVInFrag` is true for twirl/polar or `_DEPTH_DECAL`, POM, screen modes (`NBShaderInput.hlsl:1304-1314`). At `:363-368`, DepthDecal may first replace UV0.xy, so helper blend UV must use the same *effective meshTexcoord0* after that replacement, not blindly raw UV0; standard UV0.zw alternative remains unchanged. Existing `NBGraphBaseUV` already owns this effective UV0 and all UV0/1/2/packed mode evaluation; append Flipbook outputs there rather than recompute in BaseColor.
3. `ParticleProcessUV` `NBShaderInput.hlsl:883-894`: Flags1 bit15 `FLAG_BIT_PARTICLE_1_ANIMATION_SHEET_HELPER` selects `meshTexcoord0.xy * _BaseMap_AnimationSheetBlend_ST.xy + zw`, else raw `meshTexcoord0.zw`. `ForwardPass.hlsl:370-380` selects blend weight `_AnimationSheetHelperBlendIntensity` (half CBUFFER) for helper, else interpolated TEXCOORD3.x first stored as half varying. Shared pure resolver should preserve this float2 UV and half weight boundary. These two helper values are CBUFFER fields (`NBShaderInput.hlsl:33-34`), NOT old ShaderLab Properties; AnimationSheetHelper.cs writes them dynamically. Graph needs same-named blackboard hidden vector/float to receive SetVector/SetFloat, with neutral defaults; do not invent a Graph-only name or packed mode flag.
4. `ForwardPass.hlsl:598-623`: `mainTexNoise` adds equally to MainTex_UV and blendUv.xy; `BlendTexture` samples the same texture twice using identical wrap/forceLOD0 then half4 `lerp` by blendUv.z. The selected alpha is taken from the *blended* sample before mask/dissolve/lighting/alpha stages. In ordinary BaseMap path, mask and normal maps use their own UVs and are not separately flipbook-blended; a test must not imply they are. `NBGraphBaseColor` currently samples BaseMap once at `:~840` float and `:~1276` half. Refactor that one callsite per precision to a shared `NBGraphSampleFlipbookBaseV1` using existing `NBGraphSampleMap`, `NBGraphBaseMapWrapMode`, and packed NoMip flag. It must retain the CA-on Forward precedence (CA three-sample branch bypasses Flipbook), while Depth/Shadow CA is suppressed and Flipbook still applies.
5. Pass scope from `NBShader.shader`: Backface, Forward, DepthOnly, ShadowCaster have `_ _VAT _FLIPBOOKBLENDING_ON` keyword group; both exact NB screen passes have `_FLIPBOOKBLENDING_ON` separately (`:1043`,`:1168`) and no VAT; Universal2D also has Flipbook but is excluded per user. Graph F0 runtime `_FlipbookBlending` float gate adds no new shader keyword/variant axis, should affect shared BaseColor in Forward, Depth/Shadow, both NB screen; Meta/Motion/Selection remain not parity-claimed. CameraOpaque BaseMap wrap is statically Clamp per current `NBGraphBaseMapWrapMode`, and both frame samples must use that selector.
6. Existing `AnimationSheetHelper.cs` currently chooses `_W9ParticleShaderFlags(1)` or `_NBShaderFlags(1)`, then `GetInteger/SetInteger` (`:313-351`). Current SG material instead carries lossless `_NB_Flags{0,1}Lo16/Hi16`. Without an adapter, the helper writes a *different* flag and the Graph never observes bit15. F0 runtime helper candidate must read/write Graph split flags when those four properties exist (bit14 of flags0, bit22 of flags1, bit15 of flags1); preserve both 16-bit words, use float exact range 0..65535, fall back to old path unchanged. `AnimationSheetHelper` still sets `_BaseMap_ST`, Blend_ST and intensity by old names. Separate helper component integration test needed after shader parity. Do not add an alias uint property because it creates two divergent serialized flag sources.
7. Graph GUI's `NBShaderSyncService.ApplyFlipbookEnabled` returns early for Graph targets; F0 shader receives a material float toggle regardless, but Mesh UI click/GUI intent-sync and VAT exclusivity need later GUI check. If updating GUI in F0, do not alter old ShaderLab keyword sync or emit `_FLIPBOOKBLENDING_ON` on Graph. Manual material test is not GUI evidence.

B. Minimal dynamic candidate
- Append `NBFX_ResolveFlipbookUVV1` and `NBFX_ResolveFlipbookWeightV1` as pure HLSL leaf to an existing shared include (`NBShaderUVV1.hlsl` preferred); have the old `ParticleProcessUV` and ForwardPass call them, no duplicate algorithm. Re-run Frozen A vs current B after shared extraction. Graph BaseUV adds inputs UV3, Blend_ST, BlendIntensity and outputs BlendUV, BlendWeight, after all existing input slots but before old output slots; existing IDs/edges survive. Defaults `_FlipbookBlending=0`, Blend_ST=(0,0,0,0) and intensity=0 reflect old absent ShaderLab property state; normal helper needs script to populate. Graph BaseColor adds F0 inputs after all old inputs and before existing outs: FlipbookToggle, BlendUV, BlendWeight. The conditional dual BaseMap sample uses the existing raw+HDR decode/Wrap/LOD function and path, not SG Sample Texture node. Runtime active only when `_FlipbookBlending>.5`, and only on Graph supported ordinary Mesh; no runtime `DistortionMode` substitute for static CameraOpaque wrap.
- If shared extraction of exact old wrapper `BlendTexture` is too broad because it depends `TEXTURE2D`/CBUFFER, keep the wrapper and extract only pure UV/weight selection; Graph shares `NBGraphSampleMap` and the explicit two-sample branch. Do not include all of `NBShaderInput.hlsl` from Graph.
- Script must reread live Graph/BaseUV/BaseColor/AnimationSheetHelper at run time and preserve CA/FG; preview `/tmp` only, no apply. V0 is not yet integrated and must not be overwritten, but F0 and later V0 should be independently composable.

No current evidence demands official package, UniversalTarget or NBPostprocess edits. G0/GF/G3 implications unchanged.

D. Verified packed special-UV correction in preview v2
`NBShaderUVV1.hlsl:40-59` has a compile-time `_FLIPBOOKBLENDING_ON` branch. Its particle-system specialUVChannel exception requires Flags1 bits23 and19 and TEXCOORD3.yz. The Graph will not have that keyword. The dynamic candidate therefore adds one zero-initialized `flipbookBlending` field to the existing shared params struct, sets it only from the runtime Graph property in Graph BaseUV, passes UV3.yz into the existing input struct, and includes bit23 in its flags mask. Old keyword-on path stays literally the same; all old non-flipbook callers initialize the added field to zero and retain their branch. This is necessary to honor the original packed protocol without adding a novel Graph keyword. The candidate 36-case fixture includes `particle25/75` with MainTex mode 1 across Forward and both NB screen Passes to exercise this branch; it is still only a proposed test, not Gate evidence until compiled and run.

Current candidate fixture implements only Forward plus both exact NB screen Passes, 6 feed/weights (stream, helper, particle-special at .25/.75) x 2 cameras x 3 routes = 36 A/B/C cases. It explicitly does not certify DepthOnly/ShadowCaster alpha clipping, AnimationSheetHelper component lifecycle, GUI, or VFX; those need separate slice/tests. It also does not yet span the four wrap modes/LOD0, noise-on/off, CA-on precedence, or mask/normal independence from the full F0 plan, so do not call the F0 feature complete based solely on this candidate.
