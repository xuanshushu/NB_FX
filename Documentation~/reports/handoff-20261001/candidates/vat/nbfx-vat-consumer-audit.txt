V0 VAT consumer correction — package Graph, 2026-10-01 (read-only/source audit, not GPU proof)

1. SG 17.3 ordering is decisive. `Library/PackageCache/com.unity.shadergraph@2b401d56d4b3/Editor/Generation/Templates/BuildVertexDescriptionInputs.template.hlsl:6-35` computes Object/World normals, tangent, bitangent, object/world/clip-derived position and view before `VertexDescriptionFunction`. URP `.../com.unity.render-pipelines.universal@35356061dd01/Editor/ShaderGraph/Includes/Varyings.hlsl:116-135` evaluates the Graph vertex function and custom interpolators, then assigns VertexDescription.Position/Normal/Tangent back into Attributes. Thus a World Normal/Position node *inside* the vertex Graph sees original Attributes, not modified final VertexDescription blocks. The earlier V0 statement that rewiring Position/Normal blocks automatically updates SixWay vertex SH was wrong and is retracted.

2. At current Graph, `NBGraphSixWayBake` vertex CF has its NormalWS/TangentWS/BitangentWS slots wired to ordinary WorldSpace NormalVector/TangentVector/BitangentVector nodes; these read original input. Its six baked SH outputs feed both SixWay and non-SixWay `SampleSHPixel` lighting (SixBack2 bridge). Old NBShaderForwardPass.hlsl:80-140 calculates VAT first, then world normal/tangent and SixWay/OUTPUT_SH/vertex light. Minimal package-only correction: add `NBGraphVATWorldBasis` vertex CF *downstream of* VAT CF, taking VAT OutNormalOS + existing three original world-basis node outputs. When VAT off or unsupported it passes all three original vectors through exactly, preserving every existing Graph-off case. When supported SoftBody on it transforms VAT normal OS to world, keeps tangentWS (old VAT did not modify tangent), and emits a bitangent with the same orientation sign as original SG basis, so existing `NBGraphSixWayBake` sign-recovery yields old `tangentOS.w * odd`. Rewire only the three edges into `NBGraphSixWayBake`, not its math/outputs. Two-camera negative-scale and lit-SH strong A/B/C controls are mandatory; HLSL static review alone does not prove it.

3. The *later* URP Varyings pass at lines 128-206 assigns final Position/Normal and computes positionWS/normalWS, shadow bias and interpolated fragment fields from modified Attributes. SG BuildSurfaceDescriptionInputs.template.hlsl:8-49 then computes fragment NormalWS, PositionWS/VS and ViewDirWS from those varyings. Accordingly the existing Graph BaseColor CF fragment inputs NormalWS, PositionWS/VS, ViewDirWS and ScreenPosition will see VAT when final Position/Normal blocks are correctly rewired; this covers fragment Lighting/POM/NormalMap/DepthDecal/refraction routes at data-flow level, not numerical parity. SG vertex-only Fog custom interpolator is a separate exception: it must use VAT OutPositionOS before VertexOffset, matching old pre-offset clipZ. SG `ScreenPositionNode` inside vertex Graph (if any future use) remains original unless explicitly rewired. Old vertex additional-light term uses postVAT/preVO world position/normal; current Graph L0 does not support that vertex-light term, and VAT must not be used to claim it.

4. ShadowCaster/DepthOnly: old geometry path includes VAT, graph block path can carry it to the URP pass; URP Varyings shadow bias uses final `normalWS`/`positionWS`, old shader's shadow bias uses normal after VAT and position after VertexOffset. These passes require actual depth/shadow RT controls; Forward images alone cannot certify them. Old Tyflow SHADOWS_DEPTH macro is not seen in own ShaderLab, not extrapolated to Houdini.

5. Two NB screen passes: old ShaderLab lacks `_VAT` variants. Current package SubTarget clones same vertex description, so V0 candidate adds a *predefined* NB_GRAPH_NO_VAT define to both exact NB screen passes. Test needs directed renderer-list captures with VAT on/off *for Graph and old ShaderLab*, showing NB screen geometry unchanged while Forward geometry moves, on nonblack/nonuniform scene and two cameras. Do not infer no-VAT from merely seeing macro in C#; GPU path must prove.

6. V0 default identity rule: `_VAT_Toggle` default 0, no VAT influence on existing Graph mesh cases. New CF should return exact input PositionOS/NormalOS; world-basis adapter should return exact original WorldSpace N/T/B without recalc; SubTarget pass defines add no keyword axis. Root must rerun existing full mesh matrix after integration, not merely V0 cases. Unsupported VAT modes are explicitly not implemented and must not be silently labelled SoftBody parity.
