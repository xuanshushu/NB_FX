NB_FX ordinary Mesh — VAT / CustomLocal / Flipbook implementation boundary (2026-10-01, read-only audit)
Scope: current NBShader ShaderLab vs package SG URP Mesh; VFX/HDRP/UI/Sprite remain separate. This is a candidate order, not a feature reduction or Gate pass. No official package, UniversalTarget or NBPostprocess edit is evidenced as required.

1. Source facts / execution order
- NBShaderForwardPass.hlsl:80-92 starts with input.vertex/normal/tangent; _CUSTOM_LOCAL_TRANSFORM converts a world-space input to custom object space; then ApplyVAT mutates positionOS and normalOS. :94-140 calculates world position, clip/fog, normal/tangent sign, vertex SH/SixWay/vertex light. :225-265 performs VertexOffset later, recomputing position/clip but deliberately not fog, normal or vertex lighting. Thus SG must be raw position -> optional CustomLocal conversion -> VAT -> original clip/fog/normal/SH -> VertexOffset -> final clip; merely appending VAT after the existing Graph VertexOffset changes the old result. Shadow bias follows offset (:268-280).
- XuanXuanRenderUtility/Shader/HLSL/VAT.hlsl: ApplyVAT dispatches only with _VAT keyword + _VAT_Toggle >= .5, then _VAT_HOUDINI/_VAT_TYFLOW. NBShader.shader:640-654,775-787,891-896,949-954 compiles VAT/Flipbook mutually exclusive for backface/Forward/DepthOnly/ShadowCaster. NB screen passes at :1029-1043/:1154-1168 compile CustomLocal + Flipbook but no VAT. Universal2D :1278/:1292 likewise no VAT; excluded from this Mesh scope. Graph must gate VAT in those four geometry passes only, not blindly clone onto both NB screen passes.
- HoudiniVAT.hlsl:131-161 takes VAT UV1 from Mesh TEXCOORD1 (AttributesParticle.Custom1.xy) or particle UV0.zw and computes frame using _Time.y/_gameTimeAtFirstFrame/_houdiniFPS/_frameCount/_playbackSpeed/auto/manual. Particle-only packed CustomDataFlag2 nibble 7 overrides frame. SoftBody :187-229 samples pos LOD0, optional pos2 LOD0, decodes displacement using bound flags, adds position, derives normal from pos alpha or rot quaternion. RigidBody :234-328 uses TEXCOORD1/2/4 and pivot/pscale; DynamicRemesh :331-380 uses UV0 and lookup; ParticleSprite :383-517 has camera-facing geometry even if Mesh keyword permits it. All submodes remain final parity scope; first candidate below is only SoftBody.
- TyflowVAT.hlsl:418-445 computes frame (_Frame, custom frame, autoplay/loop/interp). Absolute/Relative :545-581 use Mesh TEXCOORD1 Custom1.xy, point-clamp _VATTex/texel size/decode, optional animated normals. Skin :446-544 uses up to seven bones with UV1/2/3..7 (TEXCOORD1..7), per-bone weights and TM reconstruction; particle flag explicitly returns. :420-425 tests SHADOWS_DEPTH + _AffectsShadows; repo search found no NBShader.shader definition of SHADOWS_DEPTH, so do not promise shadow suppression without generated-code/GPU evidence. Handle exact legacy behavior, not intended behavior.
- NBShaderInput.hlsl:1219-1245 binds AttributesParticle Custom1/2 TEXCOORD1/2, texcoordBlend TEXCOORD3 under _FLIPBOOKBLENDING_ON else vatTexcoord4 TEXCOORD3; VAT additional TEXCOORD4..7. Official local Shader Graph UvChannel.cs supports UV0..UV7 and UVNode outputs float4; no demonstrated UV-stream or Target hard blocker yet.

2. Flipbook is the smallest independent remaining slice, F0, before VAT geometry
- NBShaderForwardPass.hlsl:164-222,360-425 calls ParticleProcessUV; NBShaderInput.hlsl:883-894 chooses blend UV = UV0.xy * _BaseMap_AnimationSheetBlend_ST.xy + zw when Flags1 bit15 helper, else UV0.zw. ForwardPass:370-380 selects blend weight = _AnimationSheetHelperBlendIntensity for helper, else interpolated TEXCOORD3.x. :598-623 adds the same noise displacement to main/blend UV, then BlendTexture samples both with identical wrap + LOD0 flags and lerps; CA-on Forward path instead uses the three chromatic samples, so Flipbook does not silently double-apply in that branch. Depth/Shadow and both NB screen passes also have Flipbook variant; VAT and Flipbook must remain mutually exclusive in geometry. Existing Graph CF BaseColor/UV needs raw UV0.zw, UV3.x, helper ST/intensity and Flags1 bit15, appended to serialized slots/HLSL signature at the end. Distortion or screen host must follow its existing pass-specific clamp/static define, not runtime mode guessing. F0 tests: 2 divergent frame colors, helper on/off, blend 0/.25/.75/1, noise on/off, CA-on priority, four wrap modes + LOD0, Forward/Depth/Shadow/screen with two cameras, strict old/current A/B and B/C, hard controls + repeat/finite. Ordinary Mesh is not particle-stream SpecialUV parity.

3. VAT staged priority, no submode deletion
- V0 = Houdini SoftBody Mesh, then V1 = Houdini RigidBody/DynamicRemesh/ParticleSprite behavior, V2 = Tyflow Absolute/Relative, V3 = Tyflow Skin variants and all frame/customData interactions. The numerical dependency is V0 position/normal before VertexOffset and before fog/GI; F0 can be independently landed first. V0 should use same-named/default old ShaderLab material properties (NBShader.shader:92 onward) and flag gating; do not create shadow integer mode flags or new shader keywords. Graph material mode/toggle may runtime gate inside package CF, but no VAT on NB screen pass. Animation source must use Mesh UV1.xy, not particle UV0.zw or generic graph UV routing.
- For V0, extract a small *leaf* shared pure HLSL helper for frame-selection math, HVAT_VatUV, bounds decode, quaternion normal/alpha decode from HoudiniVAT.hlsl:68-124,138-149,187-225. Existing ShaderLab wrapper delegates to helper; SG vertex wrapper samples UnityTexture2D pos/pos2/rot at explicit LOD0 using each texture's sampler. Do not include entire HoudiniVAT.hlsl in Graph: it references AttributesParticle, material globals and keyword branches from old CBUFFER. Preserve float arithmetic and sample order; compare old Frozen A vs modified-old B before Graph C. A dedicated helper is justified rather than copying formula across passes. No deliberate half casts in V0 arithmetic unless old has one.
- Dynamic Graph insertion must read latest Graph/CF on application, preserve object IDs/order, and splice VAT CF output PositionOS/NormalOS into existing NBGraphVertexOffset inputs. Tangent remains raw in V0 (old SoftBody changes normal but not tangent). Also feed post-VAT/pre-VertexOffset PositionOS into FG1 fog vertex input; FG1 original-raw position is correct only while VAT is off. SG vertex Position/Normal blocks must get VO outputs so downstream SixWay vertex SH, normal lighting and generated transforms use animated geometry. The current NBGraphVertexOffset.hlsl:32-150 uses old position/normal and returns unchanged normal/tangent: appending VAT after it would be wrong. Parent currently owns central Graph, so V0 preview must be dynamic and not applied by this agent.
- V0 tests: generated 2x2 / nonuniform displacement map and independent normals; manual frame and auto time frame (frozen Unity time or manual deterministic inputs), dual-position texture on/off, compressed-normal/rot-texture branches, bounds raw/decoded branch, VAT off, VertexOffset on/off interaction, negative-scale mesh, orthographic/perspective two-camera, Forward visible nonblack B/C strict0, geometry/depth/shadow comparisons, old Frozen A/B strict0, repeat/finite/control. No fake pass if Graph import placeholder; warm GPU first. Uncovered submodes and custom particle frame explicitly pending.
- V2 Tyflow must preserve point-clamp sampler and `_VATTex_TexelSize`; not safe to reuse ordinary Graph BaseMap sampling. Packed CustomDataFlag2 nibble7 is read even on Mesh; graph must represent old `uint` split lo16/hi16 and Custom1/2 as actual streams, not a hand-entered approximation. If first V0 omits this custom frame, mark pending, not passed.

4. CustomLocal is a later *cross-cutting* C0 slice, not a mere matrix added to VAT
- NBShaderInput.hlsl:250-251,269-369 owns two material matrices, custom position/dir/normal/view transforms and determinant sign. ForwardPass:80-101 transforms input position/normal/tangent before VAT, then all positionWS/clip/normalWS and sign use custom matrices. Fragment depth decal, POM, viewDir, six-way, lighting and shadow need same effective coordinate system. A package Graph vertex adapter can calculate canonical Mesh OS output by custom matrix then unity_WorldToObject mapping, but all fragment/world/object consumers and custom odd-negative-scale must be audited; changing only Position block is insufficient. CustomLocal is enabled by old keyword in Forward, Depth, Shadow, NB screen and Universal2D; this plan excludes Universal2D but does not erase its future boundary. No evidence that SG/UniversalTarget must be patched; minimum proof threshold is an actual generated-source/API incapability after a package SubTarget/CF prototype.
- C0 tests require nonidentity and reflected custom matrices, translating/scaling mesh object independently, known view-space and normal/tangent orientation, surface+screen+depth/shadow+POM/decal, two cameras, A/B/C strict comparison and controls. Do not claim C0 from position-only test.

5. Scheduling/gate recommendation
F0 Flipbook (surface + pass branches) -> V0 Houdini SoftBody (VAT architecture+geometry) -> V1 remainder Houdini -> V2/V3 Tyflow -> C0 CustomLocal cross-cutting integration; refine if parent has a stronger dependency from current CA/FG integration. Retest VertexOffset, FG fog (its clipZ is postVAT/preOffset), SixWay, normal and depth/shadow after V0. These are candidate slices only; GUI synchronization, VFX/Particle streams, Player and performance/variant stripping remain explicit final work. No decision request to user is supported at this point.
