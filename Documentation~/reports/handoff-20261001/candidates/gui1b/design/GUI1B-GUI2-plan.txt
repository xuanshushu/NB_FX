四、GUI1B marker1→2 一次 seed 的精确合同（候选 A 已具备）
- 22 toggle/7 mode 用原同名 Hidden 真 Float Vector1ShaderProperty/m_FloatType0，不用 Integer、不生成影子旧 int words。
- 从每个 Material 自己当前的 NBShaderFlags.CheckFlagBits 读取，绝不从混合 MaterialProperty.floatValue 广播。
- 22 toggle 对应 bit on→1/off→0。7 mode 为 enabledMode 和另一二值；_ColorBlendMode enabledMode==0，必须 on→0/off→1。
- 精确29映射在 A source-manifest.json；生成时直接取当前同一数组，不另写协议表。
- 必须原 Graph signature、marker 与2foldouts都为实际 Float；全部29真实 Float schema 才升级到2；部分 schema 只保留1行为。
- version0或1升级；version>=2不再 seed；版本最后写。已有用户 Flags 对应开关“意图”不变。
- 统一 Undo.RecordObjects，UI mirrors+marker参与 Undo；原 halfwords、textures、ST/color、keywords、passes、queue、官方 Surface、原 folds 精确不动。
- 有限非法 lo/hi 仅共享读取时 clamp/round，seed 不 canonicalize 或重写原 raw Float。NaN/Infinity 不新增未经实测规则。
- 只 seed29新的 UI镜像，没有功能 seed；不重置 _EmissionEnabled/_noisemapEnabled 等已有 functional Float。
- **当前候选没有启用周期性的 mirror→flags 全 Sync**，也没有启用 Tier/UI Toolbar。这是必要安全边界，不是功能完成。

五、必须解决的权威交接：避免把用户刚改的原生 flags 又改回去
现有 fallback 可直接编辑 Flags0/1 lo/hi，还提供 Fresnel/Dissolve 的 packed 开关。
假如 seed 后全 Sync 用陈旧 UI mirror 回写所有29位，会覆盖这些实际刚编辑的 values；不允许这种无声回退。
最窄接法（在原服务与原控件处，不增加并行 protocol）：
1 原 SyncService 增加 readback UI mirror 的单一辅助函数，复用现有 binding；用于原生 packed 改变的显式通知。
2 GraphRoot.DrawPackedFlag/DrawProperty：若真正编辑 flags0/1 半字，则在已有 Undo 事务里通知同一 SyncService 从 raw word 刷新对应 mirrors；不能初始化 render 值。
   GraphRoot 只负责“编辑发生了”，不复制22/7映射。Wrap/channel/NoMip/PNoise words各走原 GUI0 hooks，不改 Flags0/1 UI镜像。
3 Shared PropertyToggle/Mode business callback 先明确编辑 mirror，再用原 ApplyToggleFlag/同一 binding 写自己拥有的 bit。
   单次改动不遍历 unrelated bindings；原材质 SetFlag no-op 保护、bit31/未知位都保留。
4 每一片向 GetSharedGraphPropertyNames 注册真正已构造的 physical props；已接 shared block 的旧 packed快捷按钮也退出 fallback，画一份。
   不是“名字加入黑名单就不画”：该 block 真 schema预检+构造+后台调用+图像测试通过后才交接。
5 最稳过渡：Graph 一般 Sync 仍 raw flags 为真值，做需要的原生编辑 readback/同一个 effective resolver；只有实际 shared callback 前向写它拥有的位。
   等29控件全部交接、raw高级编辑入口也接通知后，才考虑复用全 SyncTogglePropertyFlags；不急着新造 runtime ownership mask。
6 version2之后新的 UI-only字段再次追加，按迁移分片新增 seed，不能把29重 seed成 default。
   若已有镜像和 raw 值矛盾，不能由一般 Validate 偷猜来源；显式 setter/编辑通知决定权威，未编辑 raw preserved。

建议实际规范化字段：sourceMaterial、hostKind、MeshSourceMode、officialSurfaceType、alphaClipIntent、BlendMode、screenDistortMode、disableMainPassIntent、depth/shadow官方结果。
- 旧宿主 reader 逐项读取原物理字段和原 fallback，保持 old Resolve 输出全同。
- Graph reader 从实际 schema/material 只读：ordinaryMesh=1；_Surface(0opaque/1transparent)、_AlphaClip独立、_Blend原enum0..3；_NB_DistortionMode(0/1/2)映射 screen mode；功能名称多数与原相同。
- 注意 Transparent+AlphaClip 两者可以同时开启；不要用单个旧 _TransparentMode 抹掉这一状态。
- ToggleKeywordBindings37同表、mode分支/依赖/allowed集合/排序/Pass feature IDs共用；不造临时旧Material、不在PropertyInfoDic注入假 _TransparentMode/_BaseColor/旧packed ints。

有效态与序列化意图分离：
- intent=用户真实 functional Float/mode +现有 halfword protocol，serialized原值保留。
- effective=现有 resolver(tier, projectallowedkeywords, allowedpassIDs)+原依赖链，仅派生结果。
- Graph无多数旧 shader keywords，Enable/DisableKeyword不代表CF关闭。投影到真正 CF branch输入：新增隐藏普通 Float allow输入，非 packed bitmask/第二套协议。
- 最小首对就是 B 的 _NB_TierAllowNoise/_NB_TierAllowNoiseMask，默认1；参数入口 NoiseEnabled*=allow，NoiseMaskToggle*=allow；保留原 _noisemapEnabled/_noiseMaskMap_Toggle以及 raw flags。
- CPU投影由同一 MaterialApplier 的 host分支（可抽同文件internal helper）供 Sync/Toolbar/Validate共用，写值变化才写；无需MPB，不引入 per-material Batcher隐患。
- 这两个 allow 默认1仅维持未管理 Graph 的旧行为；不能把“所有 default1”说成Tier已支持。
- **GUI2-N pair验证阶段仍不启用全局Graph Tier编辑/Context keyword gating**：其它已实现功能尚无 gates，会出现界面消失而渲染继续的假支持。
- 全功能 gate+有效mode+pass证明齐备才开启同一个原 Tier toolbar与 Context.IsKeywordAllowed。可先后台测试Noise pair的真实效果。
- Schema readiness/version单一入口检查投影需要的全部真实props/CFconsumer，不用material shadowshader或序列化第二份int；版本2 seed完成不能自动等同“Tier ready”。
- Light-mode、RampSource、DissolveRampSource、Refraction等枚举不能简单乘0；须按实际结果只读 derived effective mode/可用分支，原用户mode不覆盖，禁用light回真正Unlit。
- SixWay真实variants与Vertex/Mixed/Pixel SH原官方keywords在同一个最终projector收口；不能继续硬写“不是SixWay就清VertexSH”，否则丢失现有后端SH能力。
- Runtime/Player质量API、build stripping当前仍exact旧shader，另轮支持。Editor物料对照不能说Player/API/variantstripping已通过。
