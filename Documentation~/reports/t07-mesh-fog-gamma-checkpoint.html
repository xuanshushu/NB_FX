普通 Mesh 雾与 Gamma：校准夹具后 16/16 严格通过

人话结论：Graph 已在普通 Mesh 中接入原 NBShader 的雾计算顺序（顶点位移前取雾因子、表面颜色后应用）与 packed bit10 的 Gamma 转换。最终 16 项真实 GPU 对照中，Frozen A、当前 Shader B、Graph C 的开/关图像两两严格相同，重复帧也严格相同；透视 Forward 雾变化有明显非零信号。但这不是“所有相机、屏幕 Pass 都有雾效果”：正交相机中原 Frozen 雾/强度响应就是 0，这里只把它作为负对照。两条屏幕扭曲 Pass 在雾处理后用屏幕采样替换 RGB，材质的雾强度变化也不影响最终图像。

固定产品/测试提交 07fb0d908b28689eb45fdd259e5dd8b81559c9c9，4 路径原始源码及 SHA。本轮只改包内 Graph 与测试，不改官方 URP/Shader Graph/Target、旧 ShaderLab Pass 标签、NBPostprocess 或 packed 协议。主 Agent 执行 Unity 串行验证；本档案归档者没有运行 Unity、改产品/中央文档、提交或 push。

为什么第一轮是 6/16，第二轮才是 16/16

初版夹具的 16 项只有 6 项通过、10 项失败，但原始指标显示这 16 项的 A/B 与 B/C 主、关闭画面一直严格 0 差。失败来自三种错误的“必须有响应”假设：强求正交相机雾响应、强求屏幕 Pass 的材质雾强度响应、以及用纯色背景去强求 CameraOpaque 的背景采样变化。这些断言与实际 Frozen/当前 Shader 行为不符，不是 Graph 像素对照失败。初轮的原 XML、306 份原始浮点帧及16份指标、日志和原测试源码完整留存。

最终夹具改为有图案的背景，使 CameraOpaque 采样确实可见；透视 Forward 保留非零雾响应的正对照；正交雾/强度与两条屏幕 Pass 的强度改按 Frozen 观察值做负对照。原有 A/B、B/C 严格 0 差及重复帧断言没有放宽。测试改动可读逐行差异，不是把失败数字直接改成通过。最终独立运行的原始 XML 为 16 通过 / 0 失败 / 0 跳过；原日志与306 份 float32 RGBA 原始帧及16份指标均保存。归档时还逐份解压这 306 帧检查有限值，逐项核对 A/B、B/C 开/关及 A/B/C 重复为 0。

准确的功能边界

16 项覆盖 Forward 的 Linear、Exponential、ExponentialSquared 雾（正交与透视），Gamma、顶点位移前取雾因子、后期颜色调整，以及 CameraOpaque/Deferred 两条定向 Pass。测试使用当前 Metal、Unity 6000.3.18f1 与当前工程色彩空间；Gamma bit10 的其他色彩空间未测。正交雾“0 响应”是与原 Frozen 一致，不表示正交雾已实现成可见效果。两条屏幕 Pass 的最终 RGB 覆盖雾计算；报告中的 ActorFogResponse 只是“有无雾时，物体画面变化减去背景自身变化”的差中差诊断，不能当成独立屏幕物体雾效果。详见主 Agent 原始指标与归档汇总。

没有执行 CA1、FG1 之后完整既有 Mesh 矩阵回归；FG1 这 16 项通过不能覆盖此前 CA1 的 11 项严格失败，也不能取代 G3/G4。两条 NB Pass 的定向测试不等于 NBPostprocess Controller/Manager 全链合成。真正 VFX、Player、首帧、其他平台/色彩空间与完整材质 Inspector/Tier 均未在本片验证。普通 Mesh 尚未全部完成，G3/G4 未放行。 档案说明 · 逐附件 SHA-256。
