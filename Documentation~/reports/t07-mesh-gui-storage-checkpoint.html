普通 Mesh：让现有 GUI 后台正确读写 Graph 参数

人话结论：现有 NBShader 界面使用的“打包开关、渐变和纹理缩放平移”后台，现在能正确保存 Graph 材质的数据。46 项实际测试全部通过，包括开关最高位、不会误改旁边的位，以及真实 GPU 对半字数据的读取。这只是把后台存储接上，不是完整 Inspector 已做好。可见界面、功能按钮与 Tier/Pass 同步、保存重导入等仍需后续接线和测试。

2026-10-01；固定产品提交 033b29f94994c0fd8b8ca25a0999c96a5427d1b6。Unity 6000.3.18f1 / 当前 URP、SG 17.3 / Metal Apple M3 Pro。主 Agent 独占隔离 clone 用 CLI 导入和测试，unityMCP 当时不可调用；归档 Agent 未启动 Unity。按 D24，本轮只针对普通 Mesh 的材质后台，没有真正 VFX 或 Player 测试。

改了什么：复用原后台，不另做一套界面或协议

  • 原 ShaderFlagsBase 的公开方法继续使用同一实现，只加入可覆写的 word 读写接缝。旧材质和所有 MaterialPropertyBlock 仍直接读写原整数，不把旧整数转成 Float。
  • 普通 Graph Material 使用其已有的两个 16 位 Float 半字保存每个 32 位 word：Flags0/1、Wrap、通道、PNoise、NoMip 和两个 UV word。保留 bit31 和不相关位，不增加影子整数属性，也不新增关键词。
  • 原渐变控件的 Count 可读取原 Integer 或 Graph Float；原纹理控件可显式绑定 Graph 的 _BaseMap_ST Vector。普通贴图默认 native ST、MatCap 不出现 ST 的行为不变。该能力尚未等于正式 Graph Root 已调用全部原控件。
  • 固定提交只改 4 个原 C# 文件与新测试/meta，未改 ShaderLab、HLSL、CBUFFER、Graph、asmdef、AssemblyInfo、官方包、Target 或 NBPostprocess。

GPU 检查不是“CPU 自己算给自己看”

测试在内存创建一个小 Shader，直接 include 产品原有 NBGraphFlags.hlsl，用 CommandBuffer.DrawMesh 渲染 Quad 到 1×1 linear ARGBFloat，并用 RGBAFloat 读回。四个通道分别输出低16位、高16位、bit31和bit0；32 对有限输入包含 0.5 / 1.5 / 2.5 / 32767.5 / 65534.5 等边界。真实 GPU 与 CPU word 的四通道严格相等，相同输入第二次捕获也严格相等，并要求不同输入产生不同输出，防止夹具根本未生效。

32 条实际首捕获读回从 XML 原日志提取，且与 Unity 日志 32 条完全一致。第二次读回只有测试内存断言，没有另存 raw/PNG。不能说归档了 64 份原始像素，也不能把这个 1×1 word 单元检查说成完整 Graph 表面渲染、Frozen/当前 A/B 或 ShaderLab/Graph B/C 图像对照。

尚未证明，不能偷换成“完整 GUI 通过”

  • UV0..8、PNoise0..5 是存储边界检查，不是所有 UV 来源都已接入渲染。PNoise 实际命名枚举仍是 0..3；4/5 只保留原字段/默认回退，不新增效果或界面选项。
  • 半字读取只做有限值 clamp/round，不自动改写原小数材质值；显式写入才规范化。NaN 的原 HLSL 转换未定义，正负 Infinity 未测，不声称它们 CPU/GPU 等价。
  • MPB 即使拥有者是 Graph，也仍写原整数属性；不代表 Graph MPB 渲染协议已支持。
  • 可见 Inspector、同一完整 Root 接入、整套 callback/seed Undo、多选混合绘制、保存及重导入持久化、Tier 有效功能投影、Pass/keyword 状态、完整 Surface 对照仍待完成。
  • 新增 optional 构造参数对现有源码调用兼容，但 CLR 构造签名发生变化，预编译调用方需重编译；跨版本/安装兼容仍按 D21 留后续。
  • 普通 Mesh 完整 G3/G4 尚未完成、未放行。没有完整 NBPostprocess Controller/Manager → 正式 RT → 最终合成链、性能/变体/SRP Batcher、冷首帧、真正 VFX 或 Player 的验收结论。
