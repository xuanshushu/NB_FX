报告索引 · D24：完整 Mesh 优先 · 上一轮普通灯光 L0

普通 Mesh 环境光两种模式已接通；20 项中 13 项零差、7 项严格失败

人话结论：SH 是“周围环境从各个方向照到物体上的光”。原 NBShader 还能选择在网格顶点先算一部分环境光，或顶点加像素混合地算。现在 Shader Graph 的普通 Mesh 能沿用这两种原有模式：改变环境光、主光、法线贴图或附加点光，旧 Shader 和 Graph 的画面都有实际反应，不是连着一个空接口。但“每个像素必须完全一样”的检查下，本轮 20 项仍有 7 项失败，最大单通道差值 0.03125；这是保留的 HDR 颜色差，不能说视觉无差，也没有提高容差或放行 G3/G4。

固定产品与测试提交 51d64f4577aaa82e72be52992f345b6008a9a0d2，仅改包内现有 Shader Graph 颜色函数和灯光测试两个文件。Unity 6000.3.18f1、URP/Shader Graph 17.3、Metal、RenderGraph。主 Agent 报告 unityMCP 不可用，故在独占隔离工程用 Unity CLI；本证据归档没有启动 Unity、改产品/测试/官方 URP/Target/NBPostprocess/保护设置或 push。

20 项具体结果

原来的 8 项 Unlit/Blinn-Phong/Half-Lambert/PBR 正交与透视对照，输入没有改，仍是 5 通过、3 失败。新加的 12 项用 Blinn-Phong、Half-Lambert、PBR × 两种相机 × 顶点/混合 SH，结果为 8 通过、4 失败，4 项都是 PBR。合计 NUnit 13 通过 / 7 失败 / 0 跳过。A 为 G0 Frozen ShaderLab、B 为当前 ShaderLab、C 为生成的 Graph；96×96 linear RGBAHalf 的中心 40×40 区域逐像素比较原始 RGBA。

  • 旧实现没有被碰坏：20 项 A/B 主画面全部严格 0 差；全部捕获整帧数值有限，本轮 B/C 主画面及控制画面的重复拍摄均为 0 差。
  • 功能确实起作用：新 12 项中，主光、环境 SH、法线贴图 mask、像素附加光的因果对照在 B 和 C 均有效。这里没有证明“顶点附加光”。
  • 新 4 项失败的原始幅度：PBR 正交顶点/混合模式仅在控制画面分别有 27/28 个像素不等，最大 0.015625；PBR 透视顶点模式主画面 53 个像素、最大 0.015625，控制 163 个、最大 0.03125；透视混合模式主画面 50 个、控制 154 个，最大均 0.03125。旧 3 项严格失败仍照旧保留，不以平均色差或肉眼观感替代规则。

20 项 NUnit 原始 XML · 逐项数值 · 无损原始帧 · Unity 日志。最终导入与测试日志未见 C# 或 Shader 编译错误。

怎么接的、为什么上一次有更多失败

Graph 在顶点阶段原本已经有一组用于六向光照的环境光数据，其中 SixBack2 恰好是对物体法线调用原共享函数 SampleSHVertex 的结果。本轮在普通灯光的像素阶段将它交给原本的 SampleSHPixel，让已有的顶点/混合关键词走与旧 Forward 相同的分支。没有新增 Graph 端口、关键词、官方包改动或新的 GUI 选项；测试是直接给材质打开现有关键词，用户界面的选择与保存仍待做。

第一次 20 项试验只有 8 通过、12 失败，其中有些“画面有没有明显改变”的测试条件本身太弱：旧 Shader 的变化也只有约 0.009 或 0.004，达不到夹具固定的 0.01/0.005 检测线，Graph 与旧 Shader 的实际图像却一致。第二次只把新增 SH 用例的测试太阳和环境光对照调强；原 8 项输入与所有严格逐像素阈值不变。第一次夹具、XML、日志和全部 raw 均保留，没有把夹具敏感度误报为功能缺失。

不能偷称“阴影检查全过”

旧 Forward 没声明接收阴影的关键词轴，但在20 项单组运行里，把阴影设置打开后，旧 PBR 透视以及本轮新增的 PBR 透视顶点/混合共 3 项并非严格零变化。它们先因其他 B/C 差异失败，所以不能仅看 NUnit 的首个失败理由而称“所有阴影不变性控制通过”。原始控制图和指标都在档；这也不等于已经验证 Graph 的接收阴影功能，留给后续人工综合检查。

随后跑了全套回归，但并非 983 张截图

同一固定产品提交还跑了 983 项 NUnit：825 通过、158 严格失败、0 跳过。原有 925 项的 154 个失败身份全部保持，新增恰是本轮 4 个 SH-PBR 失败，没有旧项新增或消失。983 项由原有 925 项普通 Mesh 测试、新增 12 项 SH 画面对照及 46 项 GUI 状态存取测试组成；GUI 46 项都通过，但只检查状态/存取，没有截图。因此实际有 937 个画面对照目录，不能说“983 项都拍了图”。983 项原始 XML · 失败身份与 GUI 数量核对。

我们也没有只核对失败名单：12,450 份 PNG 或解压后的原始像素逐份与最近一次持久证据比对，12,438 份相同，12 份不同。不同者全是上述 3 项 PBR 透视的 B/C 阴影打开图及各自重复图，已全部单独存档。每张不同图跨轮次最多差 3 个像素，有些落在严格比较区内，最大通道差 0.00390625；同一轮内部“原图/重复图”仍完全相同。在这次全套运行里，3 项“旧 Forward 开阴影后应不变”的指标由单组运行的 false 变成 true，另有两项控制差异像素数量变化。因此不能把阴影不变性描述成稳定通过，也不能抹掉单组运行的失败事实。12 份原图及指标变化 · 逐文件映射与 hash。

全套的 1,259 份非截图文件也保留：逐项指标及材质状态 JSON、92 份 Shader 警告消息与 4 份生成的 Preview Shader。日志未见 C# 或 Shader 编译错误，但确有警告记录，不能说“零警告”。元数据清单 · 完整日志。
