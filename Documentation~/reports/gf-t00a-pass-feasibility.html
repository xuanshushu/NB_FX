根因与边界

  1. 原生产 ShaderLab 分别在 NBShaders2/Shader/NBShader.shader:972–980、:1096–1104 声明两条精确 LightMode；NBPostProcessing/Runtime/RenderCameraOpaqueDistortObjectPass.cs:21 和 DisturbanceMaskRenderPass.cs:44 分别只列这些标签。前者画向相机色/深度，后者画入扰动遮罩后进行屏幕拷贝、全局纹理设置与合成；默认运行分支是 RenderGraph。Pass 缺失意味着现有精确筛选不会选中该 Graph；这是依据源码与 Shader 清单的推断，非 RT 实测。
  2. 安装的 Shader Graph Target.cs:12、SubTarget.cs:10、PassDescriptor.cs:10、PassCollection.cs:7 均为 internal；URP UniversalTarget.cs:111、UniversalUnlitSubTarget.cs:13 为 sealed。URP Unlit 的 Setup / SubShaders.Unlit 在 UniversalUnlitSubTarget.cs:54–71,214–255 内建立固定 Pass 集合；Support VFX Graph 的开关仅控制 VFX 支持。没有在当前版本发现可从 NB_FX 外部程序集向此固定集合加入两条 Pass 的公开配置点。这里是当前源码审查结论，不宣称未来版本绝对不可能。
  3. Unity 官方URP 自定义光照说明明确 Custom Function 节点不能定义额外 Shader Pass 或 RenderState；因此共享 HLSL Custom Function 无法单独补齐本缺口。VFXCodeGenerator.cs:773–802 还要求 VFX 兼容 Target 与 SRP Binder 位于同一 Assembly；NB_FX 独立 Target 不可当作已验证的简易替代。后者为当前版本源码风险，不是已运行的自定义 Target 失败测试。
  4. Compatibility 路径受 !UNITY_6000_3_OR_NEWER || (URP_COMPATIBILITY_MODE && !UNITY_6000_4_OR_NEWER) 编译条件控制；当前配置未发现 URP_COMPATIBILITY_MODE 定义。本次不能宣称已覆盖 Compatibility；即使两条 Pass 存在仍须先核验实际构建分支。

输入核验与原始证据 SHA-256 清单：G0 锁定的 85 个 include、111 个 GUI/协议/后处理输入、13 个项目配置文件均逐项 hash 匹配；5 个官方包 package.json hash 与 G0 一致。未修改 PackageCache、产品 Shader/HLSL、Target、NBPostprocess 或原材质；该 hash 核验不等同于对 PackageCache 全目录逐字节审计。
