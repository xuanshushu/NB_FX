T05/G2 · Compatibility P4/P5 中间纹理检查点

结论：隔离工程当前 Unity 6000.3.18f1 / URP 17.3.0 / Metal 的 Compatibility 模式中，不仅 P4/P5 最终画面相同，P4 实际 _CameraOpaqueTexture 和 P5 原 NBPostprocess 的 _DisturbanceMaskTex、_ScreenColorCopy1 也已分别读回。P4 EditMode 与 P5 PlayMode 各执行两次，四次 NUnit 均 1/1；29 张输出图在重复运行间逐字节相同。当前/Frozen 的中间纹理严格 0 差，P5 Mask 有非零正控制。此为受控输入切片，不代表 G2 整体放行。

按用户指示，不再追查 MatCap 的微弱颜色差。本次针对先前报告明确未测的扭曲中间数据，不改 MatCap 容差。unityMCP 未暴露，使用无界面 Unity CLI 串行验证，无需用户值守。只在 /tmp 隔离副本开启 URP_COMPATIBILITY_MODE 和 Compatibility 设置，并给测试用的临时 Renderer Feature 增加 ScriptableRenderPass.Execute 读回路径；原 NBPostprocess、生产 Shader、官方包、主工程 Assets/ProjectSettings 和正式测试源码均未改。重放与回退 · 哈希/测试汇总 · P4 临时补丁 · P5 临时补丁。

P5：Deferred原 NBPostprocess 的 Mask 在无前景、Pass 关闭、强度零时为空；当前与 Frozen 启用 Mask 严格 0 差，中心双方各 5776 像素有可见数据。_ScreenColorCopy1 非黑且有 5625 种 RGB，前景绘制不改变这份较早的复制；当前/Frozen 0 差。原 Uber 的 FLASH 控制改变 16384 像素，最终启用扭曲中心变化 5776 像素。首次 XML · 复测 XML · 数值 · Mask · Screen copy

原夹具写在指标文件中的“RenderGraph”字样是未改的固定标题；实际设置 JSON及 Unity 日志均表明此次执行的是 Compatibility。重复运行 29/29 PNG 的 SHA-256 相同；与此前相同输入的 RenderGraph 归档逐字节核对，P4 12/12、P5 17/17 图相同（P4 opaque-copy 旧图归档于 p1-p4-direct）。这只证明本受控输入下图像相同，不能推断所有画面、相机和 Controller 组合也相同；逐文件比较留档。
