这 8 项究竟测了什么

四种灯光模式分别用正交和透视相机拍普通 Mesh，96×96 linear RGBAHalf 目标，中心 40×40 区域严格比较原始 RGBA。A 是 G0 Frozen ShaderLab，B 是当前 ShaderLab，C 是生成的 Shader Graph；每项都保留无损 float32 原始帧和重复帧。六项有光模式中，主光方向、环境 SH、附加点光和法线贴图 mask 的强对照均有效；Unlit 不受这些灯光改变，是有意的不变性对照。

  • A/B 保护：8 项 Frozen 与当前 ShaderLab 的主画面均为 0 差；全帧数值有限，B/C 的同一次测试内重复拍摄均为 0 差。
  • B/C 结果：Unlit 正交/透视、Blinn-Phong 正交/透视、Half-Lambert 正交共 5 项主画面及控制画面严格 0 差。Half-Lambert 透视的控制画面 2 个像素非零（最大 0.000244140625）；PBR 正交控制画面 19 个像素非零（最大 0.015625）；PBR 透视主画面 54 个像素非零（最大 0.0078125），控制画面 170 个像素非零（最大 0.015625）。这三项在原 XML 中仍判失败。
  • 阴影的准确说法：现有 NBShader Forward 没有接收阴影的 keyword 轴，本轮只核对打开阴影设置后旧 Forward 的颜色不应改变，最终夹具对此用严格零差检查并通过。这不是“Graph 接收阴影成功”。投影阴影的 ShadowCaster 另见 DS0 36/36 报告。L0 只给 Graph 普通 Forward 增加包内 AdditionalLights 三态轴，没有修改官方 URP 程序集。

全套回归与较早试验

同一代码的合并回归共 783 项：724 项严格通过、59 项严格失败、0 跳过。59 项正好是既有 UV 22、法线贴图 34、灯光 3；失败项没有新增或消失。但我们没有只看失败名单：对其余测试留下的 9,058 个 PNG/无损 raw 数据逐份与以前的持久证据比较，全部数值/文件内容完全相同；凡是相同的才用逐文件 hash 与旧档路径替代重复拷贝。合并回归的 metrics、材质状态与生成 Preview 源仍独立保留。两个旧测试碰巧同名写入目录，最终目录是最后写入者的集合；其各自早期原始帧仍在原报告，不把合并目录误称为两份独立 raw。

前几轮的失败也保留：v1–v3 是 EditMode 测试场景夹具在渲染前失败；v4 是误 include 导致 GPU 找不到 _SixWayInfo；v5 有不正确的接收阴影控制和 RT 清理错误。它们都不是最终产品需要用户决策的卡点。v6 单片为 5/3；最终合并回归才使用提交中的严格阴影不变性检查。v6 与最终各自重复帧为零，但跨两次运行有 4 张 PBR 透视阴影控制 raw 存在不超过 0.0009765625 的差异，两个版本都完整保留，不声称跨运行字节相同。历史列表。
