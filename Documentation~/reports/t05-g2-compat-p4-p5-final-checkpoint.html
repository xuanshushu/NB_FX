T05/G2 · 当前 URP Compatibility 模式下 P4/P5 最终画面对照

结论：隔离工程在 Unity 6000.3.18f1 / URP 17.3.0 / Metal 开启 URP_COMPATIBILITY_MODE 和 Compatibility 设置后，原 NBPostprocess 的 CameraOpaque P4、Deferred P5 最终颜色切片各 1/1 通过。当前/Frozen 完全相同；关闭精确 Pass 后不改变背景，强度 0 无明显扭曲，打开后中心区域确实发生扭曲。16 张受控画面与此前同输入的 RenderGraph 归档逐字节相同。这不等于 Compatibility 中间 RT/Mask、完整 Controller 组合或 Player 已通过；G2 仍未放行。

用户已要求停止追查 MatCap 的微弱颜色差，本试验改做另一个独立缺口，不修改 MatCap 容差。unityMCP 在本会话未暴露，主 Agent 串行使用无界面 Unity CLI；无须用户值守。只有隔离副本临时改了设置及测试夹具：先用脚本设置当前 Standalone define 和 RenderGraphSettings.enableRenderCompatibilityMode，再给原 P4/P5 测试打P4/P5临时补丁：保留原场景、材质、精确 Pass 标签、背景与相机，新增 Compatibility 最终颜色断言，并跳过只适用 RenderGraph 的临时 RT 可视化 Feature。正式测试文件、产品 Shader、NBPostprocess、官方包及主工程设置未改；完整重放、输入 hash、清理。

16 张 PNG 的 SHA-256 与 RenderGraph 归档逐字节核对均为 true，包括背景、Pass-off、零强度和启用状态。此处只说明相同受控输入下最终截图一致，不能据此推断两个内部渲染路径每个 RT 都完全相同。两次有效 Test Runner 运行及 setup、cleanup Unity 进程退出码为 0，日志无 C# 编译或 Shader error 标记。误带 -quit 的首个 Test Runner 尝试没有生成 XML，未计入测试结果；详见重放说明。

隔离副本的 ProjectSettings、URP Global Settings、两份原测试和临时脚本在试验后恢复/移除，四个受保护文件与试验前 SHA-256 逐字相同；另运行无界面 Unity 编译检查，无错误标记。本报告不声称 Compatibility 的 _CameraOpaqueTexture、_DisturbanceMaskTex、_ScreenColorCopy1 被单独读回，也没有记录 RendererList 元素或 GPU draw event、做 Standalone Player、性能或复杂 Controller 组合。Dissolve Editor 冷态、GUI 端到端、Player/SVC 和其余 G2 缺口继续独立处理。
