普通 Mesh 主纹理高级 UV 对照

人话结论：Graph 的主纹理现在可以像原 NBShader 一样，选择 Mesh 的不同 UV 通道、使用旋转扭曲/极坐标，或者使用共享 UV。22 项对照中，19 项逐像素完全相同；另外 3 项各只有一个像素出现 0.00024414 的通道差（约为 0–1 范围的 0.0244%）。按用户要求不再追查这种微差，原始失败保留到最后一次人工测试，不把它们改写为通过。已有表面/Preview/采样 155 项回归全部通过。

主工程输入 4602308，包输入 15b5678，产品切片 40cd0d4。Unity 6000.3.18f1 / URP、Shader Graph、VFX 包 17.3 / Metal / RenderGraph。unityMCP 未暴露可调用工具，使用独占隔离克隆的 CLI；本轮没有真正 VFX 测试，也没有打开主工程。完整 G3/G4 仍未放行。

实现边界

  • 现有 BaseUV wrapper 复用同一个 NBFX_BuildBaseUVsV1，接入独立 float4 TEXCOORD0/1/2、原 packed UVModeFlag0/Type0 与共享 UV、Twirl/Polar 参数。低/高 16 位端口包括 half wrapper 仍是 full-float，不经 half 压缩协议。
  • 本片只连接主纹理的模式 0（UV0.xy）、1（特殊 UV）、2（Twirl/Polar）、8（共享 UV）。特殊 UV 默认是 UV0.zw；Mesh 位开启时可选 TEXCOORD1.xy 或 TEXCOORD2.xy。共享源测试覆盖 0/1/2；其它模式原编码保留，但缺少宿主输入，不能宣称已支持。
  • 其它功能贴图目前仍用原有 UVMaterialSlot 的默认 UV0.xy；没有边不等于 UV 为零。Mask/Overlay/Ramp/Dissolve 等各自高级 UV 路由在下一片补齐，不能把所有纹理强行接到主纹理 UV。
  • 未接入 CustomData 参数、UI/Flipbook、位置/屏幕/圆柱宿主模式；未验证动画速度、half 精度或 VFX。没有修改原 ShaderLab、packed 位含义、官方包、UniversalTarget 或 NBPostprocess，没有新增 keyword；Graph 的 Support VFX 设置保留，但不据此宣称 VFX 已验证。
