普通 Mesh 的深度写入与投影阴影：限定场景 36/36 通过

人话结论：在这些普通 Mesh 测试里，Graph 的 DepthOnly 能挡住后方物体，ShadowCaster 能在地面投下阴影；按材质 Alpha、遮罩、溶解及阴影裁剪设置改变时，结果与现有 NBShader 完全相同。最终 36 项严格逐像素测试全部通过。这不是“整个深度/阴影系统都做完了”，也不放行 G3/G4。

固定 DS0 产品及测试提交 999aea335d4e8cdf33a0f4cb99b5d6d7a413f198，不是随后 L0 Lighting 工作区源码。Unity 6000.3.18f1 / URP、Shader Graph、VFX 包 17.3 / Metal / RenderGraph；独占隔离 clone 的 Unity CLI 运行。主 Agent 报告 unityMCP 当时不可用。归档仅处理证据，没有启动 Unity、修改官方包、UniversalTarget、NBPostprocess、产品/Test 或主索引，也未 push。

实测内容

  • 24 项 DepthOnly：四类输入（主贴图 Alpha、Mask、Dissolve、只应影响 Forward 的功能）× 三个 Cutoff（0.25、0.5、0.8）× 正交/透视。通过真正的 RendererList 深度写入，让前方网格遮住后方绿色平面；关闭 DepthOnly 后，后方平面恢复。每项记录的 27 帧均为有效深度帧。0.8 案例另把 Cutoff 临时调回 0.5，验证“该出现时确实出现”。
  • 12 项 ShadowCaster：六类设置（Cutoff 0.25/0.5/0.8、透明固定 0.5 裁剪、透明 4×4 抖动、只应影响 Forward 的功能）× 正交/透视。使用实际 URP 主方向光、遮挡物和接收平面拍摄阴影，不是只查 Pass 名称。关闭 ShadowCaster 后阴影消失；固定裁剪与抖动有不同的可见结果。
  • 严格比较：A 为 G0 Frozen ShaderLab，B 为当前 ShaderLab，C 为生成的 Graph。36 项全部为整张 128×128 linear RGBAHalf 原始 RGBA 数值 A/B 0 差、B/C 0 差；关闭 Pass 对照、B/C 重复拍摄和 Forward-only 不变性也均为 0 差。36 项捕获均为有限值。26 项主设置有可见响应；其余有意为“该功能不该改变此 Pass”的不变性/对照案例，不当成空图假通过。

没有测到的边界

DepthOnly 测的是被明确调用时真实写入深度并发生遮挡；没有证明 URP 在所有相机/Renderer 配置下会自动选择深度预通道，也没有逐值核对深度纹理、DepthColor 等输出。ShadowCaster 测的是本次主方向光和接收平面的可见阴影；没有穷举级联、偏移、软阴影、点光/聚光灯或不同 shadow matrix。两 Pass 的完整透明/混合/顶点位移及其它 Mesh 功能交叉组合、正式 VFX、Player、NBPostprocess 的 RT 收集与合成、GUI 持久化、变体剔除、SRP Batcher 与性能均未据此验证。稳定重复帧也不等于冷首帧保证。
