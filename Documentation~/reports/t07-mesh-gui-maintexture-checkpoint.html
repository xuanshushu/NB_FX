普通 Mesh Graph 已接入现有“主纹理”编辑控件；本片 38 项通过

人话结论：Graph 材质不再只能在一长串原生属性里找主纹理；包内 Inspector 现在复用原 NBShader 的“主纹理”控件处理贴图、颜色、旋转、偏移、纹理通道及相关设置。原 ShaderLab 材质仍走原控件；Graph 的其他功能暂由原生属性入口保留，不能把本片说成“整个 Inspector 都迁好了”。本轮自动测试证明的是真实材质上的编辑后端和状态保存，不是人眼看过的完整 Inspector 布局。

固定提交 597cf3f0b76f1589dc1064bafec03aee41dd216f，8 条改动路径均有来自该提交的无损源码快照。没有改官方 URP、UniversalTarget、NBPostprocess 或原 ShaderLab Pass；测试里使用的反射只为调用现有非公开入口，不是产品实现。主 Agent 独占隔离工程的 Unity CLI 运行验证；本证据归档者没有启动 Unity、编辑产品/测试/中央文档或 push。

具体测过什么

  • 新增 GUI1A 38/38，加上此前 GUI 存取测试 46/46，独立运行合计 84/84。它们使用真实导入的 Graph/ShaderLab 材质、真实 MaterialEditor、Root、Context 和 Sync。Graph 是否有 Forward Pass 在真实 URP Camera/Renderer 环境中预热确认；不是用伪造的占位 Shader 判定。
  • Graph 与 ShaderLab 混选时，遵守 Unity 官方 MaterialEditor.HasMultipleMixedShaderValues 的保护，不把第一只材质的值抄给第二只；同为 Graph 的两只材质也分别保留原值。版本标记、8 个 packed 原始字、材质关键词/Pass 状态、撤销重做、100 次重复构造与同步、真实 .mat 保存/重导入都在测试范围。
  • 旧主纹理控件要读取 EditorStyles，测试只在真正的原生 EditorWindow.OnGUI 事件里构造它，不伪造 GUI skin。两只材质的 ST 向量编辑与 Undo 使用 Unity 实际别名关系逐值核对；最终断言没有通过放宽阈值或忽略异常来换“通过”。16 种普通 Mesh Surface/Blend/Clip 组合也检查了两条同步入口。

为什么前几轮会失败

初版完整运行 1041 项中 878 过、163 失败：旧 158 项严格失败之外多 5 项 GUI1A 夹具失败。旧控件的两个构造例子缺真正 OnGUI 环境；两个混选例子绕过 Unity 官方前置保护而触发属性报错；一个 ST 例子的初始状态假设不对。第二版独立运行 46/84，新增 38 项都在准备阶段遇到未预热的 Graph 占位 Pass，不是正式产品“缺 Forward Pass”的结论。第三版在真实 URP 相机环境预热后 83/84，余下一项是测试把 Unity 的 _BaseMap ST 原生别名当成独立字段。第四版只修夹具对该别名的逐值判定后 84/84。所有失败原始 XML、日志、夹具版本和只读官方程序集 IL 依据均保留；没有把中间尝试冒充成功的产品验证。
