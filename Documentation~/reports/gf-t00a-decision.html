Q01 / GF · 自定义 Pass 与 NBPostprocess 路线

提出：主 Agent · 2026-09-25 · 待用户选择；以下均未获批准、未实施或未 push。

问题与证据

已确认目标：同一启用 Support VFX Graph 的 Graph 资产在不修改官方包、不手改生成 Shader 下生成 NBCameraOpaqueDistortPass 和 NBDeferredDistortPass，由现有 NBPostprocess 精确选中并实现原功能。当前 6000.3.18f1 / URP、SG、VFX 17.3.0 的GF 实测：官方 VFX Unlit 模板的隔离副本支持 Mesh（4096 像素与背景不同）和 VFX 子资产，但 8 个 Pass 中没有这两条标签，FindPass 均为 -1；强制重导入仍缺失。Unity 官方说明 Custom Function 无法添加 Pass，本地 SG/URP Pass 生成对象为 internal / sealed。现有 NBPostprocess 精确筛选不匹配；RT/合成和 Player 未运行，因此“无法在当前约束下直接使用现有链路”是由 Pass 缺失与源码筛选共同推得，不能写成已实测 RT 失败。

可选路线（均需明确授权）

选项范围与功能成本 / 风险下一步验收
A · 保持原约束，暂停该路径不修改 Target、NBPostprocess、官方包，也不删功能；暂不推进依赖双 Pass 的大规模 HLSL 重构。可只读继续调查后续官方公开 API / 升级版本。最安全、零产品回归；新 VFX 路径进度停滞，仍无可交付路线。Unity 版本变化可能要求重做 G0/GF。出现明确可维护的公开扩展点后重做 GF；在此之前 GF/G1/G3 不放行。
B · 授权受限的 NBPostprocess 替代架构试验（建议先限时验证）允许主 Agent 设计并试验 Graph/VFX 的额外筛选与 RT/合成路径，不要求 Graph 自身输出这两条 LightMode；原 NBShader ShaderLab 与既有后处理分支保持原样，不能默许任何功能删减。具体实现可能需 NBPostprocess、RendererFeature 或 VFX 输出配置变化。可能增加额外绘制、RT/带宽、排序和深度/透明度复杂度；同一 Graph 的颜色与扰动数据复用仍未证明；VFX 对象选择与逐粒子数据可能需要新契约。若试验不能等价，必须再次停下，不可自动扩大范围。先提交最小设计与时间盒；测试两种扰动各自的筛选、像素/RT 读回与合成，Mesh 后 VFX；重导入、Player、性能、批处理与旧路径零回归，再按 G3 独立审核。
C · 明确批准新 VFX 路径不支持这两项扰动删减新路径的 CameraOpaque 与 Deferred distortion；原 ShaderLab 不变。与原先“范围内功能不削减”约束相冲突。实现范围较小但存在明确可见的功能缺口；必须同步更新功能矩阵、样例、验收与文档，不能声称全功能等价。用户书面确认损失范围与替代视觉后修改计划；G3/G4/G5 明确检查不支持状态；原 ShaderLab 回归仍不放宽。

另有官方包补丁/程序集伪装或新 Target 路线，但当前 D03/D07 禁止默认实施，且 VFX VFXCodeGenerator 的同程序集约束使独立 Target 风险较高；如需考虑，必须单独变更约束与提交新的版本维护方案，不属于 B 的默认授权。手改生成 Shader 不作为可维护候选。

建议与当前决定

建议先选 B 的限时技术试验，因为它仍以保留原功能为目标且不碰官方包；这不是可行性保证，也不是预先批准实现或放行 GF。若不接受 NBPostprocess 变更，选 A 并暂停受影响工作。选 C 须明确接受功能缺口。本记录当前没有用户决定；沉默不构成批准。
