GF 补充试验 · NB_FX 包内 SubTarget

主 Agent · 2026-09-25 · 技术路径初步可行；GF 尚未放行 · 未 push

后续状态：本页为结构性试验的时间点快照；功能性 GF Gate已于 2026-09-26 在当前 URP/Metal 范围放行，未将本页早期未运行项冒充当时已通过。

用户仅授权测试“自己包内扩展自定义 SubTarget”。本试验未修改官方包、产品 Shader、Target 或 NBPostprocess。它证明当前版本可从同一启用 VFX 的 Graph 与真实 VFX Output 生成两个精确 Pass / LightMode；不证明这两个 Pass 已输出正确扰动数据，也不证明 RT、合成、Player 或 G3。

范围与做法

环境沿用 G0/GF：Unity 6000.3.18f1，URP / Shader Graph / VFX Graph 17.3.0，Metal，URP-HighFidelity。此会话无可调用的 unityMCP，Unity Editor 由主 Agent 串行通过 CLI/Pipeline 验证。实时 Git 起点为主工程 d4f945e、NB_FX 12da8e8，两个工作区 clean，均未 push。

仅在 NBShaders2/Tests/PassFeasibility/SubTargetProbe/ 新增隔离资产：.asmref 通过 URP Editor asmdef 的 GUID 引用官方程序集；测试 SubTarget 仍以官方 UniversalTarget 为 Target，复用当前版本 URP Unlit 的 PassDescriptor，再插入两条测试 Pass。它们故意复用普通 Forward 着色，不是 CameraOpaque 或 Deferred 扰动实现。隔离 Graph 副本 保持 URP m_SupportVFX=true；VFX Output 副本 从现有 VFXSample.vfx 复制，仅把其中 Shader Graph 引用改为隔离 Graph 的 GUID。原始输入 hash 见清单。

实际验证

Case实测结果证据 / 限制
SUB-ASM-01测试类编译并加载于 Unity.RenderPipelines.Universal.Editor 程序集，Editor 编译成功。类型查询；这是 .asmref 的程序集归属，不是修改官方包源文件。
SUB-GRAPH-01强制重导入后，隔离 Graph 的 Shader supported、无 ShaderUtil 编译消息；10 个 Pass 中 NBCameraOpaqueDistortPass / NBDeferredDistortPass 为索引 1 / 2，名称和 LightMode 均精确匹配。Graph Pass、FindPass、重导入后原始输出。原官方 Unlit Graph 仍为 8 Pass。
SUB-VFX-01隔离 VFX 资产导入产生 VisualEffectAsset、3 个 ComputeShader、Material 和生成 Shader；生成 Shader supported、无 ShaderUtil 编译消息，8 个 Pass 中两条 NB 标签仍在索引 1 / 2。同一原始输出；证明 VFX Output Shader 的生成，不等于粒子实际出屏或 Player 测试。
SUB-MESH-01受控 128×128 Quad 测试：暂时停用 NBPostProcess RendererFeature 时，4096 像素与背景不同，中心为红色 (255,0,0,255)。finally 恢复 Feature；Renderer asset 前后 SHA-256 相同且 Feature 前后均 active。渲染命令/读回、恢复与 hash、PNG。
SUB-NBPOST-OBS保持现有 NBPostprocess active 时，同一临时 Mesh 的中心为黑色 (0,0,0,255)，与暂时停用时的红色形成受控差异。测试 Pass 当前只复制 Forward 色值，不提供后处理期望的扰动数据。原始读回、PNG。差异与现有 Feature 绘制/合成一致，但没有单独的 RendererList、RT 读回或 Frame Debugger 证据，不能据此宣称原链路功能已验证。
SUB-INTEGRITY-01此前 GF 记录的官方关键源码与 package.json hash 全部相同；产品文件无修改。最终 Editor ready、编译成功，Console 当前 groundTruth 0 Error / 0 Warning。官方包 hash 比较、Editor、编译、Console。

调试过程中有一次对 Color 属性误用 GetFloat 造成 2 条工具探针 Error，另一次以绝对 AssetDatabase 路径调用内部生成器造成 2 条路径 Warning；均保留在 Console 历史中，非 Shader 编译消息。最终 Console 的“当前 0”不表示历史记录已清除。

结论、风险和后续 Gate

可行性结论：在本机当前版本，NB_FX 自己的 .asmref + 自定义 UniversalSubTarget，能够在不改官方包、不换 UniversalTarget 的情况下，给 Graph 和 VFX Output 生成两条精确 LightMode。Unity 官方 asmref 文档描述引用程序集定义的机制；这里仅使用其程序集归属，并未声称 Shader Graph 内部的 SubTarget / PassDescriptor 是稳定公开 API。

维护风险：实现依赖 URP Editor asmdef GUID，以及 Shader Graph / URP 的 internal 类型、UniversalUnlitSubTarget 当前行为和生成器模板；升级 Unity/URP/SG/VFX 时必须重编译、重导入、重测。测试 SubTarget 没有保存完整 Unlit 属性 GUI 状态、没有实现 NB 功能 HLSL/RenderState，也没有进行变体、批处理、跨平台或 Player 审核，不能直接进入产品。

GF 仍阻塞：双 Pass 的结构性前置条件已获得实验性证据，但功能 Pass 数据、原 NBPostprocess 两条 RT/合成的独立读回、真实 VFX 粒子画面、Player 和回归仍未验证。此结果不等于 G3；是否将包内 .asmref 方案升为产品方向，应由用户确认后更新 T00A/T01/T06 与验收契约，再按可回退切片继续。

本报告只给“包内 SubTarget 可生成双 Pass”的狭义肯定结论。
