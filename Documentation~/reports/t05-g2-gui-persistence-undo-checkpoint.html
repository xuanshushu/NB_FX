T05/G2 · 原 NBShader 材质保存重载与程序化 Undo 检查点

结论：隔离工程内，原 NBShader 的一个受控材质经保存、退出 Unity、重新启动加载后，所选属性、packed flags、关键字、Pass 状态与颜色保持一致；再次调用原状态同步无变化；对 Mask 属性及其同步结果执行程序化 Undo/Redo 也能恢复。这是材质状态与 Undo API 的局部补证，不是 Inspector 点击或真实多选 GUI 验收，G2 仍未放行。

环境：Unity 6000.3.18f1 / URP 17.3.0 / Metal，完整隔离工程副本，两个独立 Unity -batchmode -quit 进程串行执行，没有打开需要用户值守的窗口。unityMCP 在本会话未暴露，故使用 Unity CLI。只在隔离副本的 Assets/Editor 临时放入批处理脚本；未改包内产品代码、主工程 Assets/ProjectSettings 或原样例材质。输入 hash 与重放步骤。

步骤实际结果原始证据
第一进程：克隆原 UnLit.mat，设 Ultra、Mesh、Mask、MaskRefine、Emission、alpha multiply 和自定义 BaseColor，调用 NBShaderSyncService.SyncMaterialState，创建临时 .mat 并保存。pass=true；Mask/Emission 关键字开启，Flags1 为 0x80200080（含最高位），主 Pass 开启、两个 Distort Pass 关闭；临时资产 YAML 已落盘。原样例与 Tier 设置 hash 不变。create.json · 保存的 .mat 原始 YAML（gzip） · 关键字段摘录 · Unity 日志核对
第二个全新 Unity 进程：从磁盘加载该 .mat，比较完整选定状态快照，再次同步。pass=true；重载状态逐字等于第一进程保存前快照，再次同步也逐字不变。由两个进程分开执行，不是同一内存材质的假“重载”。reload-undo.json · 期望快照
同一第二进程：Undo.RegisterCompleteObjectUndo 后关闭 Mask 并同步，再 Undo.PerformUndo / PerformRedo。关闭 Mask 时属性 1→0、_MASKMAP_ON True→False；Undo 后选定快照完全回到原样；Redo 后完全回到修改后的快照。临时材质随后删除。变更/撤销/重做快照 · Unity 日志核对
清理与编译检查临时 .mat、脚本及 .meta 从隔离副本移除；再运行一次无界面 Unity，进程退出码 0，三轮日志均无 C# 编译错误或 Shader error 标记。受保护原样例/Tier hash 前后不变，包内测试源码与主工程 SHA-256 一致。清理后 Unity 日志核对 · 重放与 hash

边界：本试验直接设置 Material 属性并调用原状态后端；程序化 Undo 也不是用户在 NBShaderGUI.OnGUI 里点击控件产生的 Undo。它不证明 Inspector 控件、真正多选编辑、域重载时 Inspector 生命周期、其它材质组合或 GPU 最终画面均正确。Universal2D 在该样例中保持关闭，符合用户确认的手动开启策略，不据此改 Tier 配置。后续 GUI 端到端、Player/SVC、性能以及 MatCap/Dissolve 严格失败仍需各自证据。
