T08/G5 · 产品 Graph 的真正 VFX Mesh 粒子检查点

结论：当前 Unity 6000.3.18f1 / URP、SG、VFX 17.3 / Metal / RenderGraph，在隔离工程的 Unity PlayMode 测试中，产品 Graph 连接到真正 Output Particle Shader Graph Mesh，生成的 VFX shader 保留两个精确扭曲 Pass，粒子实际存活并可见，Deferred Mask 有写入。G5 未放行。当前工具列表无可用 unityMCP，使用无可见窗口的 Unity CLI；未修改官方包、UniversalTarget、NBPostprocess 或主工程 Assets/ProjectSettings，未 push。

产品样例 NBGraphVFXMeshMinimum.vfx 从已验证的 GF Spawn→Initialize→Update→Output 粒子资产派生，但将 Output 改为 ParticleTopologyMesh，默认 Mesh 槽为 Unity 内置 Cube，不是 Quad、普通 MeshRenderer 或独立 Output Mesh。Output 的 Shader Graph GUID 指向产品 Graph；原 GF 无效纹理引用已清空，使用 Graph 白色默认纹理。资产保存后在另一 Unity 进程强制重导入，源文件 SHA-256 未被导入器改写。

首次真实 VFX 编译失败：VFX 生成器把 Graph 属性放在 GraphProperties，不是普通 Mesh 的 UnityPerMaterial 同名全局；原 Graph 的扭曲/Flags 属性又未连入输出，导致 _NB_Flags0Lo16 未声明（原失败日志）。修复只在包内：把 Pass 所需属性节点连至现有 BaseColor Custom Function，使 VFX 将其注册为 fragment 输入；BaseColor 的 Flags0 从函数实参读取；两条自定义 Pass 在 VFX 下通过生成的 GraphProperties 读取同一 Output 槽，在普通 Mesh 下仍读取材质属性。没有修改官方生成器或用材质同步代替 VFX 创作。实际 VFX 生成源码显示属性进入 GraphProperties、生成 Pass 的两个精确 LightMode，以及 VFX 参数填充函数；这一版本的 Mesh 回归仍为 10 Pass、Flags0 bit29 改变 1408 像素、Flags1 bit8 Mask 中心 49→34、Mode1/2 最终画面改变 602/145 像素。
