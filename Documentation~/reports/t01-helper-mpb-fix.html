T01 · 当前 Unity 的 MPB packed Flags 通道修复

状态：两行产品修复已实施，当前 Editor API 边界用例通过；不代表 Graph/VFX GPU、Player 或 G1 通过。环境：Unity 6000.3.18f1、URP/SG/VFX 17.3.0，macOS/Metal。unityMCP 本会话未暴露，串行使用 Unity CLI。未修改官方包、Shader、Target、NBPostprocess 或原材质，未 push。

输入与根因

XuanXuanRenderUtility/Runtime/ShaderFlagsBase.cs 输入 SHA-256 14047e8f0b03c779ccd6bcbee3d055e42819bc1356a9cccdd0b7f4d4af621ab7；修改后 40073af325968afee866efdc69043f2abb647d995afbaf97789a4c4846c5dc0d。原 SetFlagBits(MPB) 使用 GetInt/SetInt，而 Clear/Check 使用 GetInteger/SetInteger。先前原始 Editor 复现中 Set bit31 后 Check 为 false，混用通道/精度探针还显示低位丢失。只将 MPB Set 分支的两处调用改为 GetInteger/SetInteger；Material 分支、位号、默认值及公开签名不变。

复测

H1–H4 原始 CLI eval在内存 Material/MPB 上得到：H1 已播种 slot1 后 Set bit31/bit23、Clear bit31 → 0x00800001；H2 未播种 → 0x80000000，证明播种是独立责任；H3 混合高低位 → 0x40800005；H4 NBPostProcessFlags 的 Material 分支 Set/Clear/Check → 0x00002000。四项断言均为 true，临时对象已销毁，未保存资产。该证据只证明当前 Editor C# API 路径，不证明 Renderer/GPU/Player 输出或外部调用者。

改脚本后一次 CLI recompile 命令在 Domain Reload 时断连并返回 network error；重新发现 Editor 后，Editor ready、编译 completed/failed=false。Console groundTruth 为 1 Error、11 Warning；这一条 Error 是修复前刻意对 Integer Property 调用 SetInt 的探针日志，已保留原文，不是本次编译错误，未通过清空 Console 掩盖。Unity MCP 不可用，故以上均为 CLI/Pipeline 证据。

未完成与回退

MPB 初次覆写整个 packed 字前须显式从材质播种，或写入调用方持有的完整 32-bit 值；不能把两行修复误当自动继承。实际 Renderer/GPU、SRP Batcher、Player 及 Graph/VFX 的双 16-bit 浮点桥还未验证，分别进入后续功能 Gate。仅回退本两行即可恢复源文件；G0 冻结副本与原 ShaderLab 保持不变。
