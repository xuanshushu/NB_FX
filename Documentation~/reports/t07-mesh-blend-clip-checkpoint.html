普通 Mesh 混合与透明裁剪

人话结论：Graph 的普通渲染现在按 NBShader 原来的顺序处理透明混合和裁剪；两条屏幕扭曲 Pass 也按自己最终输出的透明度裁剪，而不是错误地用前一步透明度。新增对照全部通过。这不代表 Inspector、阴影或完整后处理已完成。

2026-10-01；包输入 e2bdae5，产品 58f2048，主工程输入 fbe4012。Unity 6000.3.18f1 / URP、SG、VFX 17.3 / Metal / RenderGraph；unityMCP 不可用，隔离 clone 独占 CLI。未打开主工程、未改官方包/UniversalTarget/NBPostprocess/保护设置；未运行真正 VFX 或 Player。

为什么要改

URP 自带 Unlit Graph 的输出处理不等于 NBShader：不透明时会把 Alpha 改成 1，Multiply 和预乘的处理也不同。包内自定义片元适配沿用官方顶点/Graph 生成流程，并调用原 ShaderLab 同一共享混合函数，保留“RGB 先乘原 Alpha → 必要时仅调整最终 Alpha → 按最终 Alpha 裁剪”的顺序，没有新 keyword。

实测

  • 48 项 Forward：六种混合模式 × 裁剪关闭/阈值 0.25、0.5、0.8 × 正交/透视。Frozen A/当前 B 和 B/Graph C 的主态及反事实态均严格 RGBA 0 差，重复 0、全帧有限；非黑且 Alpha=0.25 的背景，源 Alpha=0.25/0.75，强响应大于固定 0.04 门槛。
  • 13 项屏幕 Pass：前序 8 项真 B/C 对照、2 项仅 Graph uniform fallback 的分析控制，加 3 项最终 Alpha 裁剪真 B/C：Deferred 最终 Alpha=0.125 应被阈值 0.2 裁掉、被 0.1 保留；CameraOpaque 源 Alpha=0.25 但最终 Alpha=1，阈值 0.5 必须保留。11 项真 B/C 严格 0 差；不能称 13 项全是 B/C。
  • 最终 61/61，无 skip：XML · 全部指标 · 日志。

目标为 128×128 linear RGBAHalf，Forward 严格内部 64×64 ROI，屏幕 Pass 48×48 ROI；保存无损 float32 RGBA raw 与 PNG。四帧预热仅稳态，不外推冷首帧或全帧等价。

失败记录与修正

初次 13 通过/48 失败：Frozen/当前已完全相同，但普通 Forward 测试没有关闭原材质的额外扭曲 Pass，被工程 NBFeature 再绘制，导致背景和透明物体的 Alpha 不同。只修夹具，使三个临时材质只绘制 Forward；产品与阈值不变，复验全部通过。初次 XML与 source/raw/log 均保留。
