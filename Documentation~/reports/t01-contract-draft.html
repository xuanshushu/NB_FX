现有入口与必须保持的阶段

当前确有的 HLSL 入口为 VaryingsParticle vertParticleUnlit(AttributesParticle input) 与 ParticleFragmentOutput fragParticleUnlit(VaryingsParticle input, half facing : VFACE)；两个结构含具体顶点流、插值与可选 Six-Way 数据。现有辅助签名包括 BaseUVs ProcessBaseUVs(float4 meshTexcoord0, float2 specialUVInTexcoord3, float4 Custom1, float4 Custom2, float3 positionOS, float3 positionWS, float2 screenUV)（这里仅把原变量名缩写）、void ParticleProcessUV(inout ParticleUVs, float4 meshTexcoord0, float4 Custom1, float4 Custom2, BaseUVs)、half3 VetexOffset(..., out half3 offsetOS) 和 void ColorAdjustment(inout half3 result, inout half alpha, half4 customData1, half4 customData2)。完整原文以 Input 与 Forward 为准；本段不宣称新接口已经存在。

全局参数写入：局部化前的等价义务

机器清单 / 重放脚本在 Input/Forward 的函数体中找出 26 处对 16 个 UnityPerMaterial 字段（含 time）的直接赋值。按原调用链，它们不能简单删除或在 Graph Custom Function 间依赖可写全局状态：

  • UV/时间：_SharedUV_Vec.z、_BaseMapUVRotation、_MaskMapUVRotation 在旋转使用前叠加时间；_DissolveMap_ST.zw、_DissolveVoronoi_Vec4.xyzw 加 CustomData 后用于同次 UV 计算。
  • 顶点：_VertexOffset_Map_ST.zw、_VertexOffset_MaskMap_ST.zw、_VertexOffset_Vec.z 在顶点采样和位移前被 CustomData 改写。
  • 片元：_DistortionDirection.xy、_NoiseIntensity 影响累计噪声；_BaseColor 根据 VFACE 选择背面色；_DistortionDirection.z 又在色散前读取 CustomData 并缩放 0.1；_FresnelUnit.x 在 Fresnel 重映射前加偏移。
  • 颜色调整：_HueShift、_Contrast、_Saturability 在操作前由 CustomData 得出有效值。该函数位于主色阶段或 Fog 后阶段的互斥分支，不能无意执行两次。

候选迁移原则：每次调用从原 uniform 与该调用的 CustomData / 时间计算局部有效值，原精度与相同后续消费者不变；若一个调用内原写入会影响第二消费者，必须连同后续读取一起搬入同一显式状态。还需用原 ShaderLab A/B 证明多次调用、不同 Pass、Preview 没有交叉状态差异；当前尚未执行。

Flags 与版本隔离的审查结果

Flags / MPB / Graph 用例矩阵与静态模型记录 728 个纯算术向量通过、两项静态风险及五项 Unity/GPU 未运行。尤其 bit31、Wrap 最高位、CustomData 高 nibble 必须在实际 Material/Player/GPU 中复验；未播种的 MPB 对 packed 字按整值覆盖原材质位的风险不能由算术结果冒充运行时结论。GF Graph 尚无产品 Flags 输入。

依赖隔离审计确认当前 .asmref 不会按 URP 版本自动失效，且 2022.3 本地 URP14 的 Editor asmdef 与 URP17 使用同 GUID。Unity 2021.3 未安装，尚不能证明旧版可打开。2026-09-27 D21 时序更正：这项跨版本风险留待最后的 T10/G7 评估，不再阻挡当前 G1/G2；G1 只审核当前环境的程序集/Graph/资产边界。未来拆包、Samples~ 或 Version Defines 候选仍不是已批准产品方案。

当前环境追加验证（D21 后）

当前 URP/SG/VFX 17.3 依赖核查表明 GF 的 .asmref、SubTarget、测试 asmdef、Graph/VFX 资产在当前项目已解析、重导入和运行；这项依赖风险不阻挡当前 G1，但 GF 仍非产品 Graph 的 G3 证据。450 项 Feature→Property→Pass→case 候选矩阵及脚本给出 24 个功能组和 24 个计划、未执行用例组；146 项没有静态 Pass 候选、398 项没有逐属性精确 Pass 关联，不能把词法提示当作运行可达。G1 应冻结这些去向与后续验证义务，而不是在产品 Graph 尚不存在时伪称 450 项运行通过。参数频率与变体预算草案逐 Pass 统计当前 keyword 组；现有 VariantStripper 只匹配 Effects/NBShader，不得假设它覆盖新 Graph/VFX。编译后变体数与导入耗时尚需当前环境测量。

当前 Editor 的内存对象测试发现一个现存 packed Flags/MPB API 通道问题：对 slot1 写 0xC0800001，Material/MPB.SetInteger→GetInteger 保留完整有符号整数（原始结果）；SetInt→GetInt 的低位丢失，且与 GetInteger 通道不一致（原始结果）。直接调用现有 ShaderFlagsBase.SetFlagBits(..., MPB, index:1) 后，CheckFlagBits(..., MPB, index:1) 返回 false（原始结果）：前者使用 GetInt/SetInt，后者使用 GetInteger。这是当前 Editor API 实测，不是 GPU/Player 读回；另有 MPB 未从材质播种完整 packed 字的风险。调用测试中的 Material.SetInt 对 Integer Property 产生一条类型不匹配 Console Error（原始日志）；之后编译仍完成且未失败，Console groundTruth 1 Error即这条测试日志，不能写成产品编译错误或 0 Error。尚未修改产品 helper；新 Graph/MPB 桥接不能沿用该混用路径，需在独立切片修复并以实际 Renderer/GPU 复验。
