原 2 项失败的原因与修复

最初有效采样得到 AB=0、BC=0.835754395，发生在 receiver 关闭、VAT on / frame1 的主颜色比较。A/B 可见像素为 459，C 为 660；原严格判决保留为 Failed。

三者实际 VAT 均开启，Houdini / SoftBody 模式、手动帧、纹理和网格输入一致；Native 的有效 VAT keywords 也开启。差异来自验证后的坐标来源：Native 默认 _MeshSourceMode=0 表示 Particle，验证器把 Flags1 bit23 设为 1，SoftBody 读取 UV0.zw；Graph bit23 为 0，读取 UV1.xy。已有同模式 Forward 通过夹具显式令 Native Flags1=0，未经过这次验证路径。

一次 B-only 反事实只把 _MeshSourceMode 设为 Mesh(1)，调用原验证器，BC 精确变为 0；恢复后差异回到 0.835754395。最终只修测试意图：A/B 在验证前明确声明普通 Mesh，C 保持 Graph Mesh。没有直接清 bit、改算法或放宽容差。Frozen 始终使用原 Frozen shader 绘制；其测试专用名称通过 Native 临时代理解析，复制仅限共享且类型匹配的属性，这不证明 Frozen GUI / validator 等价。

A/B 450 个共享属性一致，有效/无效 keywords 与 Pass 状态一致；两项 Native 独有属性没有复制到 Frozen。原 core 保留 98 条源码断言及 private 三参数 ABI，只追加一个可选观察回调字段和调用。回读 Shader 补齐 URP Core 宏，并检查真实渲染后的编译错误。
