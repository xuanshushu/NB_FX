实施方法

  1. 读取实际安装 SG/URP 的 Target、SubTarget、CustomEditor 与 VFX 支持机制。区分公开支持扩展点、internal 类型、反射或生成代码重写；后两者不默认视为可维护方案。
  2. 最小 Graph 使用共享 HLSL File Custom Function，检查 float/half 后缀、texture/sampler、Preview 分支、生成 include、函数调用 stage 和资源重复声明。
  3. 验证代表性参数与 Flags 编码，检查实际生成 HLSL 类型；Graph Integer UI 不能视为 uint 的证据。
  4. 验证自定义 Pass / LightMode 能否随 Graph 正常导入、重新生成、构建而保留。编辑生成 Shader 仅可作调查材料，不能作为最终 Graph 方案。
  5. 在 Mesh C 组验证 NBCameraOpaqueDistortPass 与 NBDeferredDistortPass 的选择、绘制、RenderTarget、Blend 和合成，对照 B 组与原 NBPostprocess。记录 RenderGraph / Compatibility 路径。
  6. 若找不到不改官方包且可维护的途径，提交源码位置、最小失败资产、生成代码及影响功能。仅列出局部替代候选并向用户讨论，不直接实现替代管线、改 Lit/Six-Way Target 或展开 VFX 重绘方案。

验收标准

  • Graph 重新导入与 Player 构建不丢失需要的 Pass，且真实执行链路具有证据。
  • 共享 HLSL 参数、precision 与 Preview/Runtime 行为经过最小测试。
  • 官方包内容 hash 未改变；所有内部 API 风险明示，无用户未批准的替代路线。

检查结果必须关联源码/资产 hash、环境与 case ID。未运行、待环境、失败均不能写成通过。主 Agent 按Gate 规则审核后才可放行。

交付物

  • 扩展点调查、Graph 版本边界与 G3 报告；若阻塞交决策材料而非“部分通过”。
