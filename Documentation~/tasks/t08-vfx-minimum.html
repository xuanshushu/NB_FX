目标与边界

将已验证 Graph 接入真正 VFX，独立核验参数/连线/逐粒子数据、Output 渲染与 GUI 中间层。新产品使用者直接创作 VFX，不导入或同步材质。

出口：G5。返回主 Agent 与任务索引。

前置条件

G4 已通过，Graph 组织方式与 Mesh 等价问题已有结论；VFX 所需最小 Output 类型由主 Agent 与用户确认。

实施方法

  1. 读取实际 VFX Output、ShaderGraph 属性绑定和生成层源码；首选真正的 Output Particle ShaderGraph Mesh 建立固定种子、固定 timestep、单粒子固定位置的 C/D 对比。不要把独立于粒子系统的 Output Mesh 当作逐粒子验证。保留 A/B/C，不以 VFX 替换基线。
  2. 列出颜色、Alpha、UV、年龄、size、position、rotation、custom attributes 与 feature 参数的所有权。区分每 Output 状态、uniform、per-particle 和 frame 数据，检查范围和默认值。
  3. 独立试验 Output 是否能接入现有 NB GUI。不能直接嵌入时验证共享配置规则/功能定义/薄适配能否完成同一体验，明确真实公开扩展点，而非预先承诺。
  4. 检查连线参数与 Inspector 控件优先级、逐粒子值能否参与功能、不能逐粒子变化的 RenderState/keyword 的处理。既不能覆盖用户连线，也不能用每粒子关键字组合制造变体。
  5. 验证最小 Output 的空间、Bounds、生成 shader/Pass、NBPostprocess、排序与基础透明行为；与 Mesh 结果比较时控制朝向、几何、时间与相机输入。
  6. 保存并重导入 Graph/VFX Asset，重新打开工程后核对 Property Reference Name、Output 端口/连线、默认值与 RenderState；Graph 的局部 Output 设置不能被误认为修改了 Graph 资产。
  7. 让用户直接在 Graph / Output 配置；不新增 Material → VFX 导入、同步、转换菜单或持久同步状态。

验收标准

  • 至少一个用户确认的真正 VFX Output 工作，且不是普通 Mesh 模拟 VFX。
  • Output/GUI 的直接复用或薄适配方案有实际证据与可维护边界；若不可行仍为阻塞。
  • 最小 C/D 参数与 NBPostprocess 对比通过，未绕开 G3/G4 的原始问题。
  • Graph/VFX Asset 保存、重导入和重开后，最小参数绑定与连线仍有效。

检查结果必须关联源码/资产 hash、环境与 case ID。未运行、待环境、失败均不能写成通过。主 Agent 按Gate 规则审核后才可放行。

交付物

  • 可复现 C/D 证据、能力限制、G5 报告和剩余 Output 测试清单。
