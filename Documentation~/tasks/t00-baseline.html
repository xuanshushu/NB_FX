实施方法

  1. 从 NBShader.shader 出发递归列出可变 include、ShaderGUI、Flags、RendererFeature、全局纹理来源、URP 设置和样例依赖；记录内容哈希与 GUID。只复制材质不能冻结算法。
  2. 同时规划隔离 checkout 的原始重放与场景内测试专用 Frozen Shader。后者复制所有可变 NB include，重映射 include 路径、Shader 名称及 GUID；不让基线引用随后会变更的共享 HLSL。第三方依赖锁定版本并记录 hash，不改官方包。
  3. 先证明 Frozen Shader 与未改动的原始 ShaderLab 一致，再用它作为 A 组。原始材质和纹理的必要副本保持导入设置；现有用户 VFXSample 资产不是本任务的可覆盖目录。
  4. 从现有 NBShaderSamples 场景复制验证场景，预留 A 原始、B 重构、C Mesh / Graph，之后才增 D VFX。C/D 在对应阶段前标记未实现，不能展示替代效果冒充结果。
  5. 建立固定相机、对象空间、时间、随机种子、模拟步数、颜色空间、分辨率、MSAA 和后处理配置。并列展示供人工观察，数值截图轮流在同一空间位置渲染。
  6. 按工具规范发现并核验状态、编译、Console、截图、测试与 Domain Reload 恢复能力。先读状态再做授权测试，保留既有警告，不清空 Console 掩盖问题。
  7. 建立 Feature → 用例索引；已有约 19 个材质只是起点。校准截图噪声与阈值，并注入测试夹具中的受控错误证明比较器会失败，完成后移除注入。

验收标准

  • Frozen Shader 的依赖闭包完整、可复现且与真实原始结果一致；原始生产实现未被改动。
  • 基线场景、环境 manifest、工具能力与初始 Console 记录齐备；已有问题独立登记。
  • 至少一条数值/图像差异检测负例有效；阈值的确定不依赖后续实现是否失败。

检查结果必须关联源码/资产 hash、环境与 case ID。未运行、待环境、失败均不能写成通过。主 Agent 按Gate 规则审核后才可放行。
