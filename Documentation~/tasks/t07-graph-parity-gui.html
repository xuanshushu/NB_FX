实施方法

  1. 按 Feature 清单逐项接入共享函数，建立 Graph 参数 → HLSL → Pass 映射；避免把原光照结果交给另一个 Target 再算一次。
  2. 验证 Vertex 输入、UV 通道、Custom Interpolator、精度和 stage；对 VAT、高级深度和复杂光照分别设 case，不把 Unity Mesh 的成功等同 VFX 的能力。
  3. 先调查 Graph 的 CustomEditor 能否直接使用 NBShaderGUI；必要时将现有 GUI 的数据访问与配置规则抽为薄接口，继续复用 RootItem/Context/SyncService，不复制第二套面板或改 UI Toolkit。
  4. 原 ShaderLab 的 GUI、材质和名称识别规则继续不变；Graph 通过明确的 host/capability 描述适配。Graph 验证材质无需与旧材质保持相同序列化；可选测试转换不得发展成 VFX 导入产品。
  5. 用受控 Mesh 对照 B/C，覆盖混合、Alpha、Fog、深度、Stencil、背面顺序、阴影、光照和 NBPostprocess。Graph 排除 UI/Sprite/UIParticle/Universal2D，但适用效果不能默认删减。
  6. 审核生成代码、采样数、variants、SRP Batcher、FeatureLevel/SVC、Player 与性能；多选/Undo/重载/默认值/动画提示等 GUI 行为纳入回归。

验收标准

  • 所有确认效果均有 B/C 结论；差异逐条归因并经用户处理，不用“尽量”等措辞掩盖缺失。
  • 同一 NB GUI 规则与实现被复用，原路径 Inspector 无回归；无独立维护的新 GUI 副本。
  • G3 的 Pass 与 NBPostprocess 证据在完整 Graph 下仍有效。

检查结果必须关联源码/资产 hash、环境与 case ID。未运行、待环境、失败均不能写成通过。主 Agent 按Gate 规则审核后才可放行。

  • 高级状态与 Player/性能证据、G4 报告，以及交 T08 的已验证接口。

实现说明和证据索引更新到正式 HTML；原始 logs、JSON、captures 使用相对链接。使用验证报告模板，不只提交聊天总结。
