目标与边界

隔离 Unity/URP 环境输入并迁移 Geometry、VAT、深度和现有光照，保持五种光照路径、坐标及各 Pass 的一致性。

出口：由 T05 汇总进入 G2。返回主 Agent 与任务索引。

前置条件

G1 已通过；基础 Context 固定，T02/T03 的消费接口已协调。涉及现有 VAT include 的改动须单独锁定文件。

修改范围与所有权

  • /Users/bytedance/UnityProject/NBUnityProject/Packages/NB_FX/Tests/（G1 分配的 Geometry / Lighting 测试）
  • /Users/bytedance/UnityProject/NBUnityProject/Packages/NB_FX/Documentation~/reports/

目录列表不是无限授权；主 Agent 在派发前填入精确文件清单和所有者。没有列入的中央入口、协议、GUI、NBPostprocess、Assets 与 ProjectSettings 不得自行修改。官方包与旧 ParticleBase 始终禁止修改；基线副本禁止跟随实现更新。

实施方法

  1. 调查 Custom Local Transform、Vertex Offset、VAT 所需 UV0–UV7、法线、切线、实例与 Buffer 输入，拆除函数对 AttributesParticle 的直接依赖但不改变数据语义。
  2. 将矩阵、相机/深度、主光和附加光、SH、阴影等 URP 调用留在 Unity adapter；纯数学放共享层。不把 URP 宏和资源声明散布至所有模块。
  3. 保持当前光照公式、MatCap 与 Six-Way 语义。这里不是切换 Shader Graph Lit / Six-Way Target 的授权。
  4. 与 T05 对齐 Forward / DepthOnly / ShadowCaster / 扭曲 Pass 的几何与 Alpha 使用，检查阴影和深度是否使用同样的形变。
  5. 建立 VAT 类型、边界帧、缺失流、非均匀/负缩放、法线切线、屏幕深度、软粒子、雾、阴影、附加光和 Bounds 测试；对原宿主能力照旧验收。
  6. 记录 VFX 日后无法提供的候选数据需求，但此阶段不假设 VFX Output 会提供，也不提前构造替代架构。

验收标准

  • 原 ShaderLab 的几何、光照、深度和阴影在受控输入下回归一致。
  • 对 UV 流、Buffer、矩阵与 Frame 数据的依赖完全显式，Unreal 仅获得可重用边界而非实现承诺。
  • 不存在未经批准的标准 Target 替换、光照近似或 Bounds 行为改变。

检查结果必须关联源码/资产 hash、环境与 case ID。未运行、待环境、失败均不能写成通过。主 Agent 按Gate 规则审核后才可放行。

交付物

  • 对应回归用例、关键坐标数值、原路径 Pass 证据与后续 Graph 风险清单。

实现说明和证据索引更新到正式 HTML；原始 logs、JSON、captures 使用相对链接。使用验证报告模板，不只提交聊天总结。
