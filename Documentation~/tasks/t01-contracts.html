实施方法

  1. 逐项导出 Shader Properties、CBUFFER、默认值、C# 与 MPB 写入者、GUI、关键字、Pass Enable、HLSL 读点，建立机器可检查的映射。现有 450 项估计不能替代完整表。
  2. 核对 NBShaderFlags.cs、NBShaderFlags.hlsl、ShaderFlagsBase 与序列化材质；记录包括 ForceNoMip 在内的实际槽位、bit、UV/Wrap/Channel/CustomData 编码。旧 W9 文档不能替代 NBShaders2 实际协议。
  3. 定义只读参数、显式 FeatureState、Geometry / Surface / Frame Context 与输出约束；注明空间、单位、精度、默认值、采样阶段、导数依赖、允许的副作用。这里是项目内部接口，不是假定 Unity 已有 API。
  4. 标注原函数对全局参数的临时修改与顺序依赖。用局部状态替代写入时，要能解释后续消费者为何获得同值。保持原计算精度和 stage，禁止顺手优化公式。
  5. 确定 ShaderLab binding 与 Graph wrapper 的分工。完整 uint 不通过未经证明的 Float / half / interpolator 传输；16-bit 分片是候选桥接，须用高位和符号边界测试证明。
  6. 按 Feature → 参数 → Pass → case 形成追踪表。区分适用于 VFX 的效果功能和已排除的新路径宿主，不以宿主缩减为理由删除效果。
  7. 根据 GF 结果确定 Pass 生成接口与版本边界。按 uniform、逐粒子动态输入、编译期 keyword 分类 Graph/VFX 参数；记录 ShaderFeature 动态连线限制，优先避免新增 MultiCompile，并制定变体/编译时间预算。
  8. 明确 package.json、asmdef/versionDefines 与 Graph/VFX 资产的版本隔离方案，使新路径最低 6000.x 的实现不破坏原 ShaderLab 2021.3 打开与运行；不能把此问题留给最终发布阶段。
  9. 发布文件所有权和签名 v1；中央入口交 T05，GUI 交 T07，VFX 后续适配交 T08。共享接口变化先提 proposal，由主 Agent 协调，不由任一模块自行更名。

验收标准

  • 所有现有属性和协议槽位有去向，无静默删除、重编号或旧材质重新序列化要求。
  • 模块输入输出可供 T02/T03/T04 开发，采样/顺序/坐标约束明确。
  • GF 的 Pass 风险已明确；新旧路径的包依赖边界、参数频率和关键词预算有可检查结论。
  • 协议数值测试设计覆盖 bit31、复合高位、所有 packed 字段与默认状态；高风险依赖有专门 case。

检查结果必须关联源码/资产 hash、环境与 case ID。未运行、待环境、失败均不能写成通过。主 Agent 按Gate 规则审核后才可放行。
