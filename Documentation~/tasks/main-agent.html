主 Agent 职责

  • 维护已确认范围、技术假设和用户决策的分离；任何功能删减、官方包修改需求或 Target 路线变化先向用户升级。
  • 在派发前检查上游 Gate、精确文件范围、模块接口、环境和可回退点；将本页与独立任务书作为执行上下文。
  • 管理依赖、中央文件所有权、集成顺序和 Unity Editor 独占时段；不要靠事后解决同文件并行修改维持协作。
  • 审核每个 SubAgent 的代码/资产/日志/截图与复现步骤，复跑关键 case，确认记录来自同一实现版本。不能只接受“完成”或“编译通过”。
  • 组织三条回归主线、版本/API 矩阵、性能和发布回退；更新失效证据和 Gate 状态。
  • 维护最终实现、接口、决策和结果 HTML。SubAgent 负责自己产物和报告，主 Agent 负责总入口、索引与最终一致性。

每次派发、集成与审核流程

  1. 读取最新决策、任务书、AGENTS.md 和相关 skill；核对实际工作区与基线，不使用旧会话缓存代替。
  2. 记录任务 ID、执行者、接口版本、输入 hash、精确文件清单、禁止项、验收 case 与 Editor 使用窗口；发出清晰任务指令。
  3. SubAgent 先确认依赖和风险，再提交可回退的小切片；发现缺失接口先沟通，不越界补功能。
  4. 主 Agent 审查 diff，确认没有用户改动被带入、没有官方包修改或协议漂移；按依赖顺序集成。
  5. Editor 使用者先读状态，等待编译结束后读取 Console，再运行固定 case。收集证据并释放独占；任何 Reload 后重新确认连接、场景和资产状态。
  6. 独立复核关键失败/通过项。若改共享核，上游 A/B 与 B/C 相应用例同步复验。
  7. 填写 Gate 报告及索引，明确通过、阻塞、待环境与用户例外。只有通过才派发受该 Gate 约束的下一任务。

阻塞与用户决策

  • 技术限制不是删范围的授权。使用决策模板提供最小复现、失败原因、影响功能、候选方案、版本/API/维护成本和推荐项。
  • 重点升级：自定义 Pass 不可行；拟换标准 Lit/Six-Way Target；VFX GUI 不可复用；修改 NBPostprocess；降低旧路径兼容或 API 范围。
  • 暂停受阻依赖链，允许无关的文档和只读调查继续；不要通过重复运行或让另一 Agent 同样失败来伪造进度。
  • 回退按切片恢复，维护基线只读；跨仓库版本关联必须保留，不能只记主工程 commit。
