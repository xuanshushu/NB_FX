实施方法

  1. 按 Forward 原顺序记录颜色与 Alpha 中间值、Noise 影响和调试分支，列出每个模块可写的 FeatureState 字段。
  2. 逐段提取函数，保持 Overlay1、Ramp、Dissolve、Overlay2、Mask、Fresnel、深度衰减及最终输出之间的顺序，不把 Overlay1 重解释为 Emission。
  3. 将临时参数变化显式化，但保留其后续影响；复核 inactive feature 默认值，不让未启用模块改变 Alpha 或 UV。
  4. 测试 HDR/负值/零 Alpha、渐变边界、Dissolve 两端、软边、顶点色、AlphaClip、Debug、premultiply 与颜色调整交叉。
  5. Fog、光照与 NBPostprocess 输出边界与 T04/T05 联审，避免 Graph 或 Pass 再次处理。分批交 T05 在原路径验证。

验收标准

  • 孤立功能和高风险组合均有对应 case，无顺序变化或隐藏的默认值变化。
  • Alpha、clip、混合前颜色、HDR 和中间调试值可比较，不只比较最终截图。
  • 同一计算被需要的 Pass 复用，未复制第二套公式，未引入多余采样和关键字。

检查结果必须关联源码/资产 hash、环境与 case ID。未运行、待环境、失败均不能写成通过。主 Agent 按Gate 规则审核后才可放行。
