总体计划与工作顺序

先保留原路径，再验证 Mesh / Shader Graph，最后验证真正 VFX；每一阶段均需证据与独立 Gate。

更新：2026-09-25 · 计划草案 · 未执行 · 不修改官方包

完成定义

  • 普通 NBShader 使用共享 HLSL 后，确认范围内的现有功能、序列化、辅助脚本、GUI 与管线行为没有未经批准的变化。
  • NBShader_VFXGraph 使用同一功能实现；在已确认版本与图形 API 上，范围内效果和 NBPostprocess 验收通过。
  • 不修改官方包，不复制一套独立效果算法或 NB GUI；任何实现路线变化和能力缺口均有用户决策。
  • 接口、实现方法、限制、测试证据、任务交付与 Gate 状态都在 HTML 文档中持续维护。
  • Unreal 仅保留适度可移植边界，不开发 Unreal 材质、插件或通用跨引擎框架。

阶段顺序

阶段任务阶段产物出口
P0 · 基线T00：代码与配置快照、依赖闭包、样例复制、工具能力核验、差异测试环境。可复现基线、测试用例索引、工具能力表、已有问题表。G0
P0A · Pass 可行性试验T00A：在隔离测试资产上，使用启用 Support VFX Graph 的最小 Graph 验证自定义 Pass / LightMode 与原 NBPostprocess；不抽取功能 HLSL。最小资产、生成代码、绘制/RT/构建证据或明确的阻塞决策材料。GF
P1 · 契约T01：参数、Flags、执行顺序、模块输入输出、宿主适配与文件所有权。接口 v1、逐属性映射、Feature → Pass → 测试关系。G1
P2 · ShaderLab 重构T02 / T03 / T04 分模块迁移；T05 串行接入原入口并组织回归。共享功能 HLSL、保持现有入口的 ShaderLab、原路径对比证据。G2
P3 · Graph 最小方案T06：在普通 Mesh 上验证 Custom Function、参数、所需 Pass / LightMode 与 NBPostprocess。Mesh / Graph 最小链路、生成代码与 Pass 证据；失败则提供决策材料。G3
P4 · Graph 等价与 GUIT07：逐功能接入、共用 GUI、渲染状态、复杂组合、构建与性能比较。确认范围内的 Mesh / Graph 等价报告。G4
P5 · VFX 最小方案T08：将已验证 Graph 接到 VFX Output，独立验证 GUI 中间层、逐粒子参数和管线。真正 VFX 最小结果、GUI 可行性结论、Output 绑定契约。G5
P6 · VFX 完整回归T09：全部确认效果、Output 类型、复杂数据、NBPostprocess、运行状态与性能。VFX 覆盖表、差异与缺口报告。G6
P7 · 版本与交付T10：候选最低 Unity 6000.x 至 6.5、DirectX/Metal/Vulkan、Player、变体、发布回退。实际支持矩阵、构建与性能证据、限制与使用说明。G7

用户已同意将 Pass 可行性试验安排在 G0 后、G1 与大规模 HLSL 重构前。此为后续执行计划的授权，不是本轮启动命令。GF 只判断架构关键风险是否足以继续投入；不替代 G2 的 ShaderLab 回归、G3 的正式 Mesh / Graph 验收或 G5 的真正 VFX Output 验证。

ShaderLab 迁移批次

批次内容每批必做
基础协议解码、数学、打包渐变。独立数值测试＋原材质协议检查。
UV / 采样UV 模式、Wrap、ForceNoMip、Flipbook、CustomData。保留原阶段分配；检查采样数和精度。
表面主色、双叠加、Ramp、程序噪声、溶解、Mask、Fresnel。保留原顺序；测试 Alpha、调试输出和关键组合。
几何 / 环境Custom Local Transform、Vertex Offset、VAT、深度效果。检查法线、负缩放、Bounds、Depth / Shadow 一致性。
光照 / 输出五种光照、MatCap、Six-Way、雾、所有现有 Pass 输出。检查 URP 依赖、Pass 特有规则、混合和 NBPostprocess。

每批只做一个可回退的垂直切片。先接入原 ShaderLab 并对比，再允许依赖它的下一批合并。重构、行为修复和性能优化不能混在同一批提交。

变更边界

  • 默认实现范围为 NB_FX。样例场景复制、必要测试资产和隔离测试项目属于已规划例外；主 Agent 在执行前逐项列出目标路径与原因，不能借此改动无关 Assets 或 ProjectSettings。
  • 现有工作区有未提交修改和 VFXSample 资产。不得回滚、覆盖或自动纳入自己的实现；基线需记录实际工作区状态。
  • 现有 ShaderLab 的旧版本兼容要求仍来自仓库规则；新 VFX 路径允许 Unity 6000+，不等于批准删除原路径兼容代码。若共享库迫使原路径提高版本，必须另行讨论。
  • 优先研究 Graph 自定义 Pass 的原始目标；证明不可行后才提出局部替代，并等待用户决策，不预先建设 VFX 重绘架构。
  • 不为测试工程便利擅自升级 Unity、URP、SG、VFX、CLI 或 Pipeline。
