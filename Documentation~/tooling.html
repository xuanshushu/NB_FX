G0 工具能力核验

  • 确认目标 project、Editor PID/session、状态、编译、Play、当前场景和 dirty 状态。
  • Console 保留原始条目与 ground truth counts；区分历史 warning 与新增错误，不清空掩盖问题。
  • 截图验证相机、分辨率、色彩与文件读回；确认 Scene View 与 Game View 含义。
  • EditMode/PlayMode 测试执行、结果 XML/JSON、失败传播与 Player build 路径。
  • Domain Reload / Play 变化后的重新发现、会话/日志 cursor 恢复和超时处理；不能把“无新日志”当成“无编译错误”。
  • 工具超时或断连时记录失败，恢复连接后重新读取状态，禁止盲目重复可能产生资产的操作。

Unity Editor 串行协议

  1. SubAgent 提交操作申请：任务、目标、预计修改、输入、验证和恢复步骤。
  2. 主 Agent 确认前序操作结束、目标 Editor ready、无不明 dirty 状态，再安排执行窗口。
  3. 变更前读取相关对象/资产/场景状态；不得擅自保存或覆盖用户未保存场景。
  4. 脚本/资产变更后等待导入与编译，读取 Console，再运行验证；发生错误停止依赖操作。
  5. 记录操作、证据和最终状态，恢复测试环境并释放窗口。其他 Agent 不同时切场景、Play 或批量改材质。

文档维护规范

正式目录：/Users/bytedance/UnityProject/NBUnityProject/Packages/NB_FX/Documentation~/，使用半角 ~。正文是 UTF-8、独立完整的静态 HTML。每份文件可直接打开，不依赖 CSS、JS、页面外壳或生成流程。

  • 正文直接编辑对应 HTML；index.html 只列出文件入口，不维护重复正文。任务、决策和报告模板是可独立打开的 HTML 范例。
  • 代码与专业术语原文保留，说明文字中文。文档维护应同步任务、契约、决策、Gate 和证据链接。
  • 可包含表格、code、SVG 流程图、截图和 video；媒体采用相对链接，不嵌入大段 Base64。当前未生成假截图或运行视频。
  • HTML/JSON/XML/log/SVG 等文本使用普通 Git；大图和视频通过 LFS。本目录的 .gitattributes 对常见媒体明确 LFS 规则。发布离线包前确认 LFS 媒体已实际取回，而不是 pointer。
  • 报告原始日志必须删去凭据、访问令牌或无关私人内容，保留与复现有关的结构与时间。证据不得伪造或仅靠摘要替代。
  • 真正测试代码、场景、材质、shadergraph、vfx 不放进 Documentation~。该目录不会作为 Unity 测试资产入口。
  • 新任务使用独立任务模板；新决策和验证报告使用对应模板。模板占位不代表已执行或已批准。
