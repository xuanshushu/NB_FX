基线、场景与回归方案

三条验证主线使用可重放输入、冻结代码与独立证据。截图相似不能代替 Pass、协议和构建验证。

冻结原始实现

只复制材质不构成基线。材质仍会引用被重构的 shader/HLSL。必须冻结 Shader、递归 include、功能 Flags、VAT/光照工具和采样配置，才能持续对照。

建议采用双保险，实际路径与资产操作由 T00 在执行开始时提交：

  1. 保存当前 commit、未提交 diff、未跟踪依赖清单和逐文件 SHA-256。保存 Unity、URP、SG、VFX、Renderer/Quality、贴图导入、材质、脚本输入与测试参数。
  2. 建立隔离的原始基线 checkout / 工程，包含确实需要的未提交内容。原工程不回滚、不清理；禁止包含凭据或无关大文件。
  3. 为同场景对标建立 test-only baseline shader 与依赖闭包，使用独立测试 Shader 名和 GUID，所有会变化的 NB include 指向冻结副本。新 GUID 的映射必须记录；不能把原 .meta GUID 复制成冲突。
  4. 冻结材质与贴图/importer；不可变大资产可按 hash 引用，但若其导入设置要变化，必须隔离。GUI 不得在打开 baseline 材质时重新同步并改写它。
  5. 验证“原工程冻结结果”与“同场景 baseline 副本”一致，记录仅为隔离而变更的 Shader 名、GUID、路径；若不一致，G0 不通过。

Baseline 副本仅是不可编辑的测试参考，不是第二套产品实现。真正由 Unity 加载的基线 Shader、测试脚本、场景与材质必须放在导入范围内；Documentation~ 只保存说明与证据。

可重放输入

  • 固定 camera、projection、resolution、Render Scale、MSAA、color space、exposure、light、fog、Quality 和 Renderer 设置。
  • 固定 scaled/unscaled/script time、VAT frame、随机 seed、模拟步数、warmup 和播放状态。不能只固定随机 seed 却任由 deltaTime 改变。
  • 先用静态或受控单粒子建立 Mesh / VFX 对照，再测试真实模拟。不同粒子运动结果不拿来伪造逐像素等价。
  • 记录纹理/importer、材质、Mesh、Graph、VFX、脚本和配置 hash；保留原始场景色与中间 RT。
  • 为每个测试记录输入、期望、操作、捕获帧与清理恢复步骤；多相机和全局状态需检查是否跨测试泄漏。

高风险组合

  • Twirl / Polar＋Shared UV＋CustomData；Flipbook＋特殊 UV。
  • Noise＋Chromatic Aberration＋Dissolve＋Mask；双 Overlay＋Color Adjustment＋Premultiply。
  • POM＋Normal＋Lighting；Six-Way＋Flipbook＋Shadow。
  • VAT＋Vertex Offset＋Custom Local Transform；透明阴影＋Dissolve＋Mask。
  • Distort＋Alpha Refine＋主 Pass 禁用；Portal / Stencil＋Depth 效果。
  • 原 ShaderLab 与新路径同屏写入扭曲场，多对象重叠和多相机。

采用单功能全覆盖、成对组合和风险驱动多功能链，而非无边界穷举所有开关。每项必须能追踪到功能 ID 与阶段 Gate。

NBPostprocess 专项

  • 两种扭曲分别验收：CameraOpaque 的采样源/绘制时点，与 Deferred 的透明后场景复制/扭曲场/最终组合。
  • 检查 RG 有符号值、清屏值、源 Alpha 混合、降采样、正负方向、零扭曲、重叠顺序和极值。
  • 捕获 _DisturbanceMaskTex、_ScreenColorCopy1 和最终输出；不能只看最后颜色。
  • 检查 ZWrite/ZTest、Stencil、深度附件、软粒子和主 Pass 开关；不得污染无关对象或重复绘制普通颜色。
  • 检查 Game / Scene、多个相机、分辨率/Render Scale/MSAA、适用的 RenderGraph/Compatibility 路径，以及原 NBPostprocess 其他效果组合。
  • T00A 在重构前用隔离原型提前探测 Pass；G3 再在实际共享 HLSL 和启用 Support VFX Graph 的产品候选 Graph 上证明生成、选择与执行；VFX 阶段才证明同一契约在生成的粒子绘制中成立。

正确性与性能标准

同设备同 API 先追求零差异；以基线重复渲染误差和 RT 精度预先校准容差，不能失败后倒推阈值。HDR 使用绝对与相对误差；Alpha 边界、Depth、Distort 分别统计，辅以局部最大误差和可视化，不能只看整图均值。

协议丢位、缺 Pass、错误空间、错误时序、丢阴影、NaN/Inf、原材质破坏不属于可接受的小误差。已有基线问题单独登记；修复必须独立授权和提交。

记录相同输入下的 GPU 时间分布、CPU 提交、Draw/Pass 数、纹理采样、变体数、构建大小、导入时间、插值与资源压力。原路径不增加无意义采样/Pass/variant，保持其适用条件下 SRP Batcher 兼容。VFX 单独衡量模拟和绘制成本，不以普通 Mesh batching 结论代替。

新路径性能预算在 G3/G5 最小原型后、完整验收前由用户确认。测试须固定硬件、API、分辨率、粒子数、warmup、采样时长及重复次数。

另设持久化回归：保存 Graph/VFX Asset，重新导入、关闭重开工程和版本升级后，核对 Graph Property Reference Name、端口、Output 参数连线、默认值、RenderState 与生成 Pass 的绑定；VFX 不需要材质导入流程，但用户创作的绑定不能静默丢失。
